## 1. 项目定位

### 1.1 这是什么

一套 **ITO（IT 运维）指挥中心驾驶舱**。使用者是运维负责人、服务台主管、SRE 或值班经理，他们需要在一屏内快速判断：

- 当前整体是否健康？
- 工单压力是否异常？
- 告警集中在哪里？
- 核心服务链路有没有问题？
- SLA 是否达标？
- 资源是否接近瓶颈？
- 谁在值班？接下来有哪些变更？

因此它的核心不是“展示数据”，而是**支撑判断**。

### 1.2 这类内容的关键词

`指挥中心` · `运行态势` · `高密度` · `可扫读` · `运维语义` · `克制的实时感` · `仪表盘/技术台账`

### 1.3 它不是什么

- 不是营销页、官网首页、产品介绍页；
- 不是通用后台管理模板；
- 不是纯视觉概念稿，不能牺牲指标含义换好看；
- 不是一屏只放一个大数字的“数据可视化海报”；
- 不是失控的蓝紫霓虹、玻璃拟态、圆角大卡片、悬浮阴影堆叠的 AI 风格大屏；
- 不是可以随意改字体、改主色、改栅格的自由创作。

### 1.4 适合 / 不适合的任务

| 适合在这套体系里做 | 不适合直接套用这套体系 |
| --- | --- |
| 新增一个运维指标面板 | 改成产品营销落地页 |
| 做工单中心 / 告警中心 / 资源视图等下钻页 | 做电商、内容社区、个人主页 |
| 接入真实工单、告警、SLA 接口 | 做登录 / 注册 / 权限管理全套后台 |
| 替换成公司真实服务名、团队名、指标 | 把大屏改成移动端优先的响应式页面 |
| 优化拓扑、图表、事件流的信息表达 | 整体换肤、换字体方向、换主色 |

判断标准：新需求是否仍然服务于“运维人员在一屏内判断系统态势”。如果不是，先确认是否应该另起一个项目视觉体系。

## 2. 视觉基准

### 2.1 气质

**Deep-space mission control / HUD 数据墙**。

- 深海蓝黑底，像暗室里的指挥舱；
- 冷白文字，不用纯白；
- 青蓝是“主强调 / 数据流 / 交互”，青绿是“健康 / 恢复”，琥珀黄是“注意 / 告警 / 新建”，紫色是“变更”，砖红是“严重 / 失败”；
- 结构靠 14px 斜切角、1px 渐变描边、HUD 标题栏、编号徽标和刻度建立；
- 发光只出现在有信息含义的地方：链路、节点核心、数值、扫描光带；不要整屏泛光。

### 2.2 色彩令牌

定义位置：`assets/css/style.css` 的 `:root`。

| Token | 值 | 语义 |
| --- | --- | --- |
| `--bg-0` | `#01060e` | 页面最底层 |
| `--bg-1` | `#031020` | 深色底 |
| `--bg-2` | `#04182d` | 抬升底色 |
| `--panel` | `#061a30` | 面板底色参考 |
| `--panel-deep` | `#031225` | 面板深部 |
| `--text` | `#e9f8ff` | 主文字，冷白 |
| `--text-soft` | `#a9cbe2` | 次级文字 |
| `--muted` | `#7b9fbc` | 说明文字 |
| `--dim` | `#4f7392` | 微标签、辅助信息 |
| `--cyan` | `#35e0ff` | 主强调 / 数据流 / 当前态 |
| `--blue` | `#2f8bff` | 信息态 / 次级强调 |
| `--green` | `#2ff0a8` | 健康 / 恢复 / 正向 |
| `--yellow` | `#ffcf3f` | 注意 / 告警 / 新建工单 |
| `--purple` | `#b57bff` | 变更 / 计划动作 |
| `--red` | `#ff5c72` | 严重 / 故障 / P1 |
| `--orange` | `#ff9d3c` | 告警分布强调 |

| `--line-strong` | `rgba(78,220,255,.55)` | 强调描边 |

**色彩规则**

- 青蓝不承担“健康”语义；健康必须是青绿。
- 琥珀黄只用于注意/告警/新建，不要拿来做全局主色。
- 红色只用于真正的故障/P1/高风险，不要拿来做装饰。
- 背景允许低透明度的蓝色径向光晕和网格，不要出现大面积高饱和蓝紫渐变。
- 状态色必须成体系：正常=青绿，告警=黄，故障=红，监控中=青，变更=紫，暂停/弱化=灰蓝。

### 2.3 字体

| 用途 | 字体栈 | 特征 |
| --- | --- | --- |
| 中文正文/标题 | `"Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif` | 系统黑体，清晰、克制 |
| 数字/英文大值 | `"Bahnschrift", "DIN Alternate", "Segoe UI", ...` | 科技感、tabular 数字 |
| 英文微标签/时间 | `"Cascadia Mono", "Consolas", ...` | 等宽、机械感 |

**字号层级（1920 画布）**

- 顶栏主标题：28px / 600 / 字距 `.13em`，带青蓝光晕
- 面板标题：16px / 600 / 字距 `.10em`
- 英文微标签：9px / 大写 / 字距 `.16em`
- KPI 主数字：28–34px / 500 / 行高 1
- 健康临期主数字：42px；SLA：26px
- 图表/列表正文：10–11px；辅助说明 9.5–10px
- 底部辅助信息：9.5px
- 最小字号不低于 9px；不要用 6–7px 的“蚂蚁字”制造虚假密度。

### 2.4 面板语言

每个面板由同一套 HUD 结构组成：

```
 ╱ 01 │ 任务健康  TASK HEALTH ─────────── 标签 ╲   48px
 │                                                │
 │  body：指标 / 图表 / 列表 / 拓扑               │   自适应
 │                                                │
 ├────────────────────────────────────────────────┤   28px（可选）
 │ 判定窗口 24h               覆盖 4 个专业组      │
 └────────────────────────────────────────────────┘
```

**固定细节**

- 14px 斜切角：左上 / 右下切角，用 `clip-path` 实现，外框 1px 青蓝渐变；
- 标题栏 48px，左侧渐隐色块 + 底部 1px 强调线；
- 标题前有 2px 强调竖条和两位编号徽标 `01–11`，徽标底色跟随模块强调色；
- 标题中文为主，英文为 2–4 个词的全大写微标签；
- 面板底色是深蓝渐变 + 极轻径向光，不允许大面积亮色填充；
- 底栏固定 28px；面板内边距以 14px 为主，列表可通栏；
- 模块强调色：健康=绿、工单=青、告警=橙、总览=蓝、拓扑=青、事件=绿、变更=紫、SLA=青、资源=黄、值班=绿。

### 2.5 六个必须保留的识别点

如果后续必须做简化，优先保住这六点，否则就不再是同一套设计：

1. **深海蓝底 + 青蓝发光线**：不是墨黑、不是蓝紫霓虹、不是玻璃拟态。
2. **14px 斜切面板 + 渐变描边 + 彩色编号徽标**：这是整套界面的结构签名。
3. **中文标题 + 全大写英文微标签 + 中央标题舱**：`任务健康 / TASK HEALTH`、`ITO 智能运维管理平台`。
4. **Bahnschrift 类数字 + 单位后缀 + 低强度辉光**：`470 件`、`96.2%`、`6h 12m`、`72.8%`。
5. **30 天任务流量沙盘**：期初 + 新增 → 闭环 + 在办，流动光带与斜切节点；不是通用力导向图，也不是专业组列表。
6. **顶栏实时时钟 + 底部运维快讯 + 轻扫描光带**：保留“指挥中心正在运行”的时间感。

## 3. 画布与布局

### 3.1 画布

- 设计尺寸：**1920 × 1080**；
- `.stage` 固定尺寸，JS 用 `transform: translate(-50%,-50%) scale(...)` 等比缩放居中；
- 屏幕比例不一致时保留黑边，不要重排；
- 页面禁止横向滚动；
- 顶栏 **88px**，底部快讯 **36px**，主区域剩余 **956px**。

### 3.2 栅格

### 4.2 任务流量沙盘

- 不再出现专业组四层孪生或外部系统节点。

### 4.3 任务类型构成

- 5 类任务切片树图，面积按数量分配，不再重复专业组在办数；
- 巡检 38 / 变更 31 / 开发 27 / 维保 19 / 其他 13，合计 128；

- 底栏左侧直接显示其他明细「试验 2 · 操作 5 · 工单 3 · 综合 3」，右侧显示「变更 + 开发 45%」。

### 4.4 超期时长分布

- 4 个时长区间：<1 天 1、1–3 天 2、3–5 天 2、≥5 天 2，合计 7；

- 状态轮播不改全局超期数，始终为 7；仅焦点任务状态变化。

### 4.5 值班与授权

- 值班为「一人一周、7×24」模型，每周一 08:00 交接；
- 本周值班者大号显示，7 天周条按 `meta.today` 高亮今天；

- 不再出现值班主管、白班、夜班、备班或在岗人数。

### 4.7 维保计划

### 4.9 巡检执行矩阵

## 5. 内容与数据规范

### 5.1 文案

- 中文主文案 + 英文微标签；
- 英文是技术标签，不是装饰性翻译：`SERVICE MESH`、`ON-CALL BOARD`、`OPERATIONAL PULSE`；
- 使用运维领域词：工单、告警、变更、值班、SLA、MTTR、MTTA、P95、CMDB、vCPU；
- 数字必须带单位：`286 单`、`38ms`、`4.8 Gbps`、`2.1 TB / 3.1 TB`；
- 时间统一 `HH:MM`（24 小时制）；日期 `YYYY.MM.DD 周X`；
- 禁止：`Lorem ipsum`、`xxx`、emoji、空洞口号、感叹号堆叠、“极致/赋能/一站式”等营销词。

### 5.2 数字一致性

这是最容易露馅的地方，必须逐项核对：

- 健康分层 109 + 12 + 7 = 128；
- 沙盘 86 + 384 = 470，342 + 128 = 470；闭环 72.8% + 在办 27.2% = 100%；
- 中心轮播只改变焦点条与在办节点描边，不改变流量数字；
- 今日新增 10、闭环 8、净流入 +2（10 − 8 = 2）；
- 近 30 天新增 384、闭环 342、期初积压 86（86 + 384 − 342 = 128）；
- 近 7 天新增 102、闭环 90；
- 任务类型 38 + 31 + 27 + 19 + 13 = 128；
- 超期时长 1 + 2 + 2 + 2 = 7；
- 后台组织架构四组在办 42 + 33 + 29 + 24 = 128；
- 值班 1 人/周；重点授权覆盖 11 / 11。

## 6. 动效与实时模拟

### 6.1 动效清单

| 动效 | 时长/节奏 | 目的 |
| --- | --- | --- |
| 面板入场 | 700ms，延迟 40–250ms，轻微上移 + 淡入 | 首屏编排 |
| 告警/故障脉冲 | 2–2.6s 循环 | 状态注意 |
| 链路流动虚线 | 3.4s / 6s 循环 | 数据流 |
| 拓扑雷达扫描 | 18s 旋转 | 态势感 |
| 底部快讯 | 46px/s 无缝滚动 | 实时信息 |
| 新事件 | 600ms 淡入 + 左移高亮 | 变化感知 |
| 数字增长 | 1.3s ease-out | 首屏加载 |

### 6.2 实时模拟节奏

- 事件流：每 **9s** 新增一条，最多保留 14 条，展示最近 6 条；
- 资源负载：每 **6s** 小幅抖动，存储波动更小；
- 刷新时间 & 巡检时间：每 **5s** 更新；
- 时钟：每 1s 更新；
- 随机新增事件要避免连续重复同一条模板。

### 6.3 暂停与静态

- 顶栏暂停按钮切换 `live` 与 `.stage.is-paused`；
- 暂停时冻结：事件新增、资源抖动、刷新/巡检时间戳、快讯、雷达、链路流动、节点脉冲、LIVE 点；顶栏日历时钟保持走时；
- 按钮图标在暂停时变为播放三角，文案变为“数据已暂停”，恢复时还原；
- `?still=1`：关闭面板入场、雷达扫描、快讯滚动、脉冲，数字直接到最终值，供截图导出；
- 遵循 `prefers-reduced-motion`。
