## 1. 项目定位

### 1.1 这是什么

一套 **ITO（IT 运维）指挥中心驾驶舱**。使用者是运维负责人、服务台主管、SRE 或值班经理，他们需要在一屏内快速判断：

- 当前整体是否健康？
- 工单压力是否异常？
- 告警集中在哪里？
- 核心服务链路有没有问题？
- SLA 是否达标？
- 资源是否接近瓶颈？
- 谁在值班？接下来有哪些变更？

因此它的核心不是“展示数据”，而是**支撑判断**。

### 1.2 这类内容的关键词

`指挥中心` · `运行态势` · `高密度` · `可扫读` · `运维语义` · `克制的实时感` · `仪表盘/技术台账`

### 1.3 它不是什么

- 不是营销页、官网首页、产品介绍页；
- 不是通用后台管理模板；
- 不是纯视觉概念稿，不能牺牲指标含义换好看；
- 不是一屏只放一个大数字的“数据可视化海报”；
- 不是失控的蓝紫霓虹、玻璃拟态、圆角大卡片、悬浮阴影堆叠的 AI 风格大屏；
- 不是可以随意改字体、改主色、改栅格的自由创作。

### 1.4 适合 / 不适合的任务

| 适合在这套体系里做 | 不适合直接套用这套体系 |
| --- | --- |
| 新增一个运维指标面板 | 改成产品营销落地页 |
| 做工单中心 / 告警中心 / 资源视图等下钻页 | 做电商、内容社区、个人主页 |
| 接入真实工单、告警、SLA 接口 | 做登录 / 注册 / 权限管理全套后台 |
| 替换成公司真实服务名、团队名、指标 | 把大屏改成移动端优先的响应式页面 |
| 优化拓扑、图表、事件流的信息表达 | 整体换肤、换字体方向、换主色 |

判断标准：新需求是否仍然服务于“运维人员在一屏内判断系统态势”。如果不是，先确认是否应该另起一个项目视觉体系。

## 2. 视觉基准

### 2.1 气质

**Deep-space mission control / HUD 数据墙**。

- 深海蓝黑底，像暗室里的指挥舱；
- 冷白文字，不用纯白；
- 青蓝是“主强调 / 数据流 / 交互”，青绿是“健康 / 恢复”，琥珀黄是“注意 / 告警 / 新建”，紫色是“变更”，砖红是“严重 / 失败”；
- 结构靠 14px 斜切角、1px 渐变描边、HUD 标题栏、编号徽标和刻度建立；
- 发光只出现在有信息含义的地方：链路、节点核心、数值、扫描光带；不要整屏泛光。

### 2.2 色彩令牌

定义位置：`assets/css/style.css` 的 `:root`。

| Token | 值 | 语义 |
| --- | --- | --- |
| `--bg-0` | `#01060e` | 页面最底层 |
| `--bg-1` | `#031020` | 深色底 |
| `--bg-2` | `#04182d` | 抬升底色 |
| `--panel` | `#061a30` | 面板底色参考 |
| `--panel-deep` | `#031225` | 面板深部 |
| `--text` | `#e9f8ff` | 主文字，冷白 |
| `--text-soft` | `#a9cbe2` | 次级文字 |
| `--muted` | `#7b9fbc` | 说明文字 |
| `--dim` | `#4f7392` | 微标签、辅助信息 |
| `--cyan` | `#35e0ff` | 主强调 / 数据流 / 当前态 |
| `--blue` | `#2f8bff` | 信息态 / 次级强调 |
| `--green` | `#2ff0a8` | 健康 / 恢复 / 正向 |
| `--yellow` | `#ffcf3f` | 注意 / 告警 / 新建工单 |
| `--purple` | `#b57bff` | 变更 / 计划动作 |
| `--red` | `#ff5c72` | 严重 / 故障 / P1 |

| `--line-strong` | `rgba(78,220,255,.55)` | 强调描边 |

**色彩规则**

- 青蓝不承担“健康”语义；健康必须是青绿。
- 琥珀黄只用于注意/告警/新建，不要拿来做全局主色。
- 红色只用于真正的故障/P1/高风险，不要拿来做装饰。
- 背景允许低透明度的蓝色径向光晕和网格，不要出现大面积高饱和蓝紫渐变。
- 状态色必须成体系：正常=青绿，告警=黄，故障=红，监控中=青，变更=紫，暂停/弱化=灰蓝。

### 2.3 字体

| 用途 | 字体栈 | 特征 |
| --- | --- | --- |
| 中文正文/标题 | `"Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", "Noto Sans SC", sans-serif` | 系统黑体，清晰、克制 |
| 数字/英文大值 | `"Bahnschrift", "DIN Alternate", "Segoe UI", ...` | 科技感、tabular 数字 |
| 英文微标签/时间 | `"Cascadia Mono", "Consolas", ...` | 等宽、机械感 |

**字号层级（1920 画布）**

- 顶栏主标题：28px / 600 / 字距 `.13em`，带青蓝光晕
- 面板标题：14px / 600 / 字距 `.13em`
- 英文微标签：7.5–9px / 大写 / 字距 `.18–.3em`
- KPI 主数字：34px / 500 / 行高 1
- 健康度：27px；SLA：24px
- 图表/列表正文：9–10.5px
- 底部辅助信息：8px
- 最小字号不低于 7px；不要用 6px 的“蚂蚁字”制造虚假密度。

### 2.4 面板语言

每个面板由同一套 HUD 结构组成：

```
 ╱ 01 │ 全域健康  FLEET HEALTH ─────────── 标签 ╲   44px
 │                                                │
 │  body：指标 / 图表 / 列表 / 拓扑               │   自适应
 │                                                │
 ├────────────────────────────────────────────────┤   26px（可选）
 │ LAST SWEEP 20:07:54         COVERAGE 12/12     │
 └────────────────────────────────────────────────┘
```

**固定细节**

- 14px 斜切角：左上 / 右下切角，用 `clip-path` 实现，外框 1px 青蓝渐变；
- 标题栏 44px，左侧渐隐色块 + 底部 1px 强调线；
- 标题前有 2px 强调竖条和两位编号徽标 `01–11`，徽标底色跟随模块强调色；
- 标题中文为主，英文为 2–4 个词的全大写微标签；
- 面板底色是深蓝渐变 + 极轻径向光，不允许大面积亮色填充；
- 底栏固定 26px；面板内边距以 14px 为主，列表可通栏；
- 模块强调色：健康=绿、工单=青、告警=橙、总览=蓝、拓扑=青、事件=绿、变更=紫、SLA=青、资源=黄、值班=绿。

### 2.5 六个必须保留的识别点

如果后续必须做简化，优先保住这六点，否则就不再是同一套设计：

1. **深海蓝底 + 青蓝发光线**：不是墨黑、不是蓝紫霓虹、不是玻璃拟态。
2. **14px 斜切面板 + 渐变描边 + 彩色编号徽标**：这是整套界面的结构签名。
3. **中文标题 + 全大写英文微标签 + 中央标题舱**：`全域健康 / FLEET HEALTH`、`ITO 智能运维管理平台`。
4. **Bahnschrift 类数字 + 单位后缀 + 低强度辉光**：`286 单`、`99.972%`、`38ms`、`4.8 Gbps`。
5. **雷达网格 + 六边形节点 + 正交流动链路的服务拓扑**：不是通用力导向关系图。
6. **顶栏实时时钟 + 底部运维快讯 + 轻扫描光带**：保留“指挥中心正在运行”的时间感。

- 设计尺寸：**1920 × 1080**；
- `.stage` 固定尺寸，JS 用 `transform: translate(-50%,-50%) scale(...)` 等比缩放居中；

- 页面禁止横向滚动；

### 4.1 专业组运行总览

- 四个指标等宽：在办 128、近 30 天闭环 342、超期 7、任务 SLA 96.2%；
- 数据来自 `assets/js/ito-data.js` 的 `dashboard`；在办副行显示 4 个组 / 8 名成员；
- 右上角是中心演示控制：自动 10s / 暂停 / 上一步 / 下一步 / 四状态直切；
- 状态：`日常 → 超期 → 处置 → 闭环`，只改变焦点任务与专业组状态，全局保持 128 / 342 / 7 / 96.2%；
- 演示控制必须与顶栏“暂停实时数据”联动：全局暂停时中心轮播停止，恢复后继续。

### 4.2 专业组数字孪生

- 四层斜切结构：应用组 42、通信组 33、在线组 29、基础设施组 24；
- 每组三个指标：在办、成员、超期；
- 层级宽度 82% / 88% / 94% / 100%，形成纵深；
- 超期状态：通信组在「超期」状态为砖红，其余有超期的组为琥珀黄；
- 数据来源：`ITO_DATA.groups`、`dashboard.groupActive`、`staff`、任务超期计算；
- 不再出现 API 网关、CMDB、数据中台等外部系统节点。

### 4.3 专业组负荷

- 四组在办横向条，最长条为当前最高组；
- 底栏显示平均负荷与最高组数值；
- 42 + 33 + 29 + 24 = 128，必须与顶部在办一致。

### 4.4 超期分布

- 按专业组拆分 7 项超期：应用 1、通信 2、在线 2、基础设施 2；
- 底栏“超期合计 7 项”必须与总览一致；
- 状态轮播不改全局超期数，始终为 7；仅焦点任务状态变化。

### 4.5 值班与授权

- 今日值班主管、白班、夜班来自 `ITO_DATA.duty`；
- 在岗人数 = 主管 + 白班 + 夜班 + 备班；
- 授权覆盖来自 `ITO_DATA.auths` 的有效授权数，显示为 `7 / 8`；
- 底栏显示交接时间。

### 4.6 SLA 达成

- 自绘 270° 弧形仪表盘，不是 ECharts 默认仪表盘；
- 刻度 44 格，每 11 格一个长刻度；
- 弧线从深蓝渐变到青蓝、浅青，外圈有虚线装饰环；
- 中心 99.972% + “SLA 达成率”；
- 右侧三行指标：MTTR、MTTA、一次解决率，各自带环比；
- 底栏“连续 31 天达成服务目标” + “TARGET 99.95%”。

### 4.7 资源负载

- 四条：处理器、内存、存储、网络出口；
- 分段式负载条（repeating-linear-gradient），不是实心进度条；每行强调色：CPU 青、内存 绿、存储 黄、网络 蓝；
- 阈值：`< 70%` 青绿，`70–84.9%` 黄，`≥ 85%` 红；
- 每行显示当前百分比、容量/P95 等辅助信息；
- 底栏说明自动扩容状态。

## 5. 内容与数据规范

### 5.1 文案

- 中文主文案 + 英文微标签；
- 英文是技术标签，不是装饰性翻译：`SERVICE MESH`、`ON-CALL BOARD`、`OPERATIONAL PULSE`；
- 使用运维领域词：工单、告警、变更、值班、SLA、MTTR、MTTA、P95、CMDB、vCPU；
- 数字必须带单位：`286 单`、`38ms`、`4.8 Gbps`、`2.1 TB / 3.1 TB`；
- 时间统一 `HH:MM`（24 小时制）；日期 `YYYY.MM.DD 周X`；
- 禁止：`Lorem ipsum`、`xxx`、emoji、空洞口号、感叹号堆叠、“极致/赋能/一站式”等营销词。

### 5.2 数字一致性

这是最容易露馅的地方，必须逐项核对：

- 健康服务 121 + 告警 5 + 故障 2 = 纳管服务 128；
- 中心列四组在办 42 + 33 + 29 + 24 = 128；
- 超期 1 + 2 + 2 + 2 = 7；中心轮播不改全局数字；
- 今日工单新建 286、已解决 271、积压 15（286 − 271 = 15）；
- 近 7 天新建 2,062、已解决 1,970、积压 92；
- 值班 5 行 / “5 人在线”；中心列授权覆盖 7 / 8；
- 重大事件 0 起 → P1 事件为空，不能同时出现活跃 P1。

### 5.3 数据结构

> 中心列已于 2026-11 改为「专业组数字孪生」，以下事件 / 变更 / 拓扑结构仅保留为旧版参考；当前中心列读取 `assets/js/ito-data.js`。

**事件**

```js
{
  time: "20:04",              // HH:MM
  level: "P2",                // P1 | P2 | P3
  svc: "工单中心",
  desc: "API 响应时间超过阈值，已自动扩容",
  status: "处理中",            // 处理中 | 监控中 | 已恢复 | 待响应
  cls: "processing"           // processing | watching | resolved | waiting
}
```

状态与颜色映射：

| 状态 | class | 颜色 |
| --- | --- | --- |
| 处理中 | `processing` | 黄 |
| 监控中 | `watching` | 青 |
| 已恢复 | `resolved` | 青绿 |
| 待响应 | `waiting` | 红 |

**工单趋势**

```js
today: {
  labels: ["08","09",...,"20"],
  created: [14,18,17,22,26,21,31,34,27,30,22,16,8],   // Σ286
  resolved:[10,15,13,20,24,19,28,31,25,29,21,25,11],  // Σ271

week: {
  labels: ["周一",...,"周日"],
  created: [...],   // Σ2062
  resolved: [...],  // Σ1970
  newTotal: 2062, doneTotal: 1970, backlog: 92
}
```

**资源负载**

```js
RES_BASE = { cpu: 42.6, mem: 68.2, disk: 74.1, net: 31.8 }
```

**拓扑节点**

- 状态类：`status-ok` / `status-warn` / `status-crit`
- 数据属性：`data-name` / `data-status` / `data-req` / `data-lat` / `data-owner`
- 工具提示由 `data-*` 直接生成，不要在 JS 里复制一份节点字典。

## 6. 动效与实时模拟

### 6.1 动效清单

| 动效 | 时长/节奏 | 目的 |
| --- | --- | --- |
| 面板入场 | 700ms，延迟 40–250ms，轻微上移 + 淡入 | 首屏编排 |
| 告警/故障脉冲 | 2–2.6s 循环 | 状态注意 |
| 链路流动虚线 | 3.4s / 6s 循环 | 数据流 |
| 拓扑雷达扫描 | 18s 旋转 | 态势感 |
| 底部快讯 | 46px/s 无缝滚动 | 实时信息 |
| 新事件 | 600ms 淡入 + 左移高亮 | 变化感知 |
| 数字增长 | 1.3s ease-out | 首屏加载 |

### 6.2 实时模拟节奏

- 事件流：每 **9s** 新增一条，最多保留 14 条，展示最近 6 条；
- 资源负载：每 **6s** 小幅抖动，存储波动更小；
- 刷新时间 & 巡检时间：每 **5s** 更新；
- 时钟：每 1s 更新；
- 随机新增事件要避免连续重复同一条模板。

### 6.3 暂停与静态

- 顶栏暂停按钮切换 `live` 与 `.stage.is-paused`；
- 暂停时冻结：事件新增、资源抖动、刷新/巡检时间戳、快讯、雷达、链路流动、节点脉冲、LIVE 点；顶栏日历时钟保持走时；
- 按钮图标在暂停时变为播放三角，文案变为“数据已暂停”，恢复时还原；
- `?still=1`：关闭面板入场、雷达扫描、快讯滚动、脉冲，数字直接到最终值，供截图导出；
- 遵循 `prefers-reduced-motion`。

### 7.3 新增一个面板

```html
<section class="panel panel-xxx">
  <div class="panel-head">
    <div class="ph-left">
      <i class="ph-idx">11</i>
      <h2>面板标题</h2>
      <span class="ph-en">ENGLISH LABEL</span>
    </div>
    <span class="head-tag">状态</span>
  </div>
  <div class="panel-body">
    <!-- 指标 / 图表 / 列表 -->
  </div>
  <div class="panel-foot">
    <span>AUX INFO</span><span>AUX INFO</span>
  </div>
</section>
```

步骤：

1. 放进对应列，按现有栅格调整行高，不要随意破坏三列比例；
2. 复用 `.panel-head` / `.panel-body` / `.panel-foot` / `.seg` / `.head-tag` 等现有类；
3. 标题前编号顺延；
4. 新样式写在 `style.css` 对应分组，使用 `:root` 令牌；
5. 如需要图表，沿用 `ECharts` + 深色 tooltip + 细线 + 低饱和面积渐变；
6. 在 1920×1080 下截图，确认面板不裁切、不溢出、字号不低于 7px。

### 7.4 接入真实数据

- 工单趋势：替换 `TREND` 数据，保持 `newTotal` 与序列求和一致；
- 事件流：WebSocket/SSE 收到消息后，构造成事件对象，插入 `events` 头部，`fresh: true`，调用 `renderEvents()`；
- 资源：替换 `RES_BASE`，按阈值重绘 `paintResources()`；
- 拓扑：更新节点 `class` 与 `data-*` 属性即可，tooltip 自动读取；
- 暂停语义：暂停仅冻结 UI 刷新，后端连接不应断开；恢复时补一次全量刷新；
- 不要把接口调用散落在视图层；可在 `app.js` 外新增 `api.js`，但保持无构建、无框架即可运行。

### 7.5 视觉修改边界

允许：

- 在现有色彩体系内微调亮度/透明度；
- 替换业务字段、服务名、人员名、时间数据；
- 增加同语言的面板、图表、指标；
- 优化字号、间距、对齐，只要不破坏整体密度和栅格。

不允许（除非用户明确要求）：

- 换主色/改字体方向/改斜切角风格；
- 改成响应式多断点布局；
- 删除现有面板来“留白”；
- 引入 UI 框架、组件库、构建工具；
- 用外部 CDN 代替本地 ECharts；
- 把真实可交互控件换成假控件。

## 9. 同系列页面怎么扩展

如果要继续做 **工单中心 / 告警中心 / 资源视图 / 变更管理 / 分析报表** 等页面：

- 保留同一套顶栏、底部快讯、色彩、字体、面板组件；
- 仍然使用 1920×1080 + 三列/两列栅格，不改成普通后台；
- 模块发生变化，但信息密度、文案语气、数字单位、状态色保持一致；
- 当前驾驶舱是“总览”，下钻页应更聚焦单一主题，而不是重复所有模块；
- 不要引入新的视觉方言（例如一个页面赛博朋克、一个页面极简白底）。

## 11. 管理后台

`admin.html` 是同一产品的浅色管理视图，不占用 1920×1080 大屏画布，也不沿用深海蓝 HUD。

- 与大屏共享品牌、组织、站点、版本与任务口径；大屏顶栏提供「管理后台」入口，后台顶栏与登录页提供「驾驶舱大屏」返回入口。
- 后台采用暖白底 + 橙色主强调 + 系统字体 + 轻阴影卡片；不要套用大屏的斜切面板、青蓝发光或三列栅格。
- 任务、巡检、值班、维保、授权、消息、配置与日志均要求真实交互；不允许假按钮。
- 后台完整结构、角色矩阵、数据契约与验收清单见 [`ADMIN.md`](ADMIN.md)。
- 后台截图检查尺寸：1920 × 1080、1600 × 1000；窄屏需确认侧边栏转为抽屉。
