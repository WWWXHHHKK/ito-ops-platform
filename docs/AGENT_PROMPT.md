# 给其他 Agent 的交接提示词

把下面整段复制给接手的 agent（包括需要跨会话/换模型的情况）。把最后的 `【本次任务】` 换成你的实际需求。

---

## 直接复制的版本

```text
你接手的不是一个新项目，而是现有的「ITO 智能运维管理平台 · 运维驾驶舱」。

在写任何代码之前，必须按顺序阅读：
1. AGENTS.md
2. docs/HANDOFF.md
3. preview.png（视觉基准，必须看）
4. index.html、assets/css/style.css、assets/js/app.js

先用 5 行以内向我确认你理解的内容标准：
- 这是什么类型的界面；
- 目标用户是谁；
- 视觉方向是什么；
- 哪些东西不能改；
- 本次任务要新增/修改什么。

我想要的不是“再做一个好看的大屏”，而是延续现有的这套：
- ITO 运维指挥中心，不是营销页、通用后台或纯视觉概念稿；
- 深海蓝黑底 + 冷白文字 + 青蓝（主强调/数据流）+ 青绿（健康/恢复）+ 琥珀黄（注意/告警/新建）+ 紫色（变更）+ 砖红（严重），不要失控的蓝紫霓虹、玻璃拟态、圆角大卡片；
- 中文主文案 + 英文微型技术标签；数字带单位；运维术语准确；
- 1920×1080 固定画布，三列 404 / 1fr / 404，面板 14px 斜切角、青蓝渐变描边、编号顺延、44px 标题栏；
- 高信息密度但可扫读，每个面板都回答一个真实运维问题；
- 动效克制，实时事件/资源/时钟可模拟，但必须能暂停；
- 原生 HTML/CSS/JS + 本地 ECharts，无构建、无外部 CDN；
- 数字和状态必须自洽（健康分项=总数，拓扑图例=节点数，趋势汇总=序列和，变更条目=底栏数量）。

工作方式：
- 不要重做视觉、不要换主色/字体/栅格，除非我明确要求；
- 新增面板沿用 panel-head / panel-body / panel-foot 结构，编号顺延；
- 新增交互必须真实可用，不要放假按钮；
- 改完必须在 1920×1080 下截图检查，控制台无报错，面板无裁切/溢出；
- 用 ?still=1 检查静态大屏效果；
- 完成后告诉我：改了哪些文件、加了哪些数据、怎么验证的。

如果我的要求与现有规范冲突，先指出冲突并问我，不要默默改掉基准。

【本次任务】
（在这里写你要做的事。例如：新增“自动化任务”面板；把事件流接 WebSocket；再做一个告警中心下钻页；替换成我们公司的服务名和指标。）
```

## 更短的版本（只做小改动时）

```text
先读 AGENTS.md、docs/HANDOFF.md，并看 preview.png。这是现有的 ITO 运维驾驶舱，请严格沿用现有视觉语言、1920×1080 栅格、面板结构、数据单位和状态色，不要重做设计。改完在 1920×1080 截图自检、确认控制台无报错，并说明验证方式。

本次任务：【填写】
```

## 如果你只想让 agent 理解“我要的内容”，先不让它改代码

```text
请先不要写代码。阅读 AGENTS.md、docs/HANDOFF.md 和 preview.png，然后回答：
1. 这个项目是什么、给谁用？
2. 它和普通后台/营销页/赛博朋克大屏的区别是什么？
3. 视觉系统由哪些颜色、字体、面板语言组成？
4. 哪些内容规则和数字一致性必须遵守？
5. 如果让你新增一个面板，你会怎么保持同一套语言？

回答通过后，再等我给具体任务。
```

## 交接时建议一起发的东西

| 内容 | 原因 |
| --- | --- |
| `preview.png` | 一张图胜过描述，先对齐“感觉” |
| `AGENTS.md` | 项目级硬规则，agent 会自动读取 |
| `docs/HANDOFF.md` | 布局数值、模块规格、数据契约、验收清单 |
| 本次任务一句话 | 明确是新增面板、下钻页、接接口还是改数据 |
| 不可改项 | 例如“主色、字体、三列栅格、01–11 编号不要动” |

## 判断对方是否真的理解了

合格的复述应该包含这些关键词中的大部分：

`ITO 运维` · `指挥中心 / 驾驶舱` · `高密度可扫读` · `深海蓝 + 青蓝 HUD + 青绿/黄/紫/红状态色` · `中文主文案 + 英文微标签` · `1920×1080 固定画布` · `斜切面板 / 编号徽标 / 渐变描边` · `数字自洽` · `克制的实时动效` · `不是营销页/普通后台/失控的蓝紫霓虹`.

如果对方只回复“好的，做一个炫酷的运维大屏”，说明它还没理解，继续把 `preview.png` 和 `docs/HANDOFF.md` 发给它。
