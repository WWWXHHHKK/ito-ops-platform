# ITO 任务 SLA 综合得分说明

> 版本：v1.1  
> 方案：A 加权综合分  
> 适用范围：驾驶舱 SLA 面板、任务考核解释、月度运维复盘

## 1. 文档目的

驾驶舱的 SLA 从单一百分比调整为综合得分，用于回答三个问题：

1. 当前整体交付是否按时？
2. 超期风险是否受控？
3. 闭环效率是否达标？

综合得分不能替代单项指标。任何分数变化都必须能下钻到按期闭环率、超期率、平均闭环时长和对应任务明细。

## 2. 统计口径

| 指标 | 口径 |
| --- | --- |
| 统计周期 | 当前演示月（2026-11）已闭环任务 |
| 按期闭环率 | 按期闭环任务数 ÷ 已闭环任务数 |
| 超期率 | 当前超期任务数 ÷ 当前在办任务数 |
| 平均闭环时长 | 已闭环任务从发起到闭环的平均时长 |
| 目标闭环时长 | 8 小时 |
| 数据刷新 | 演示环境随快照刷新；真实环境按日或实时接口刷新 |

> 接真实接口后，统计周期、目标闭环时长和权重应作为可配置项维护，不允许只改展示值。

## 3. 计算公式

```text
SLA 综合得分 =
  按期闭环率 × 60%
  + 超期控制率 × 25%
  + 时效达成率 × 15%
```

其中：

```text
按期闭环率 = 按期闭环任务数 ÷ 已闭环任务数 × 100%
超期控制率 = 100% - 超期率
超期率 = 当前超期任务数 ÷ 当前在办任务数 × 100%
时效达成率 = 100 - max(0, 平均闭环小时 - 8) × 5
```

约束：

- 时效达成率最低 0 分，最高 100 分
- 综合得分保留 1 位小数
- 无已闭环任务时，显示「数据不足」，不强行计分

## 4. 当前演示数据计算

```text
按期闭环率：88.9%
超期率：5.5%
平均闭环时长：6h 12m
目标闭环时长：8h
```

计算过程：

```text
按期得分 = 88.9 × 60% = 53.34
超期控制率 = 100 - 5.5 = 94.5
超期控制得分 = 94.5 × 25% = 23.63
时效得分 = 100 × 15% = 15.0
SLA = 53.34 + 23.63 + 15.0 = 91.97 ≈ 92.0 分
```

## 5. 等级规则

| 分数 | 等级 | 解释 |
| --- | --- | --- |
| ≥ 95 | S | 优秀 |
| 90–94.9 | A | 良好 |
| 80–89.9 | B | 达标 |
| 70–79.9 | C | 需关注 |
| < 70 | D | 需整改 |

当前得分：`92.0 分 · A 级`

## 7. 内部解释话术

> SLA 综合得分不是简单的按期率，而是由按期闭环、超期控制和闭环时效三个维度加权计算。当前 92.0 分，说明整体按期交付和闭环效率较好，超期控制仍有提升空间。点击分数可以查看三个分项和对应的任务明细。

## 8. 管理规则

- 权重调整必须记录版本和生效日期
- 目标闭环时长调整必须同步大屏和月报
- 统计周期调整必须同步大屏和月报
- 分数变化必须能追溯到分项指标
- 不允许只展示分数、不展示计算依据
- 分数下降时，优先查看超期率，再查看按期率与平均闭环时长

## 9. 常见问题

### 为什么按期率 88.9%，SLA 却有 92 分？

因为 SLA 不只考核按期率。超期率控制较好，平均闭环时长低于 8 小时目标，两个分项拉高了综合得分。

### 为什么权重是 60 / 25 / 15？

- 60%：按期交付是 SLA 的核心
- 25%：超期风险直接影响生产稳定
- 15%：闭环效率是结果指标，不单独决定 SLA

### 超期率怎么算？

```text
当前超期任务数 ÷ 当前在办任务数
```

当前演示数据为 `13 ÷ 238 ≈ 5.5%`。

### 平均闭环时长超过 8 小时怎么扣分？

每超过 1 小时，时效达成率扣 5 分，最低 0 分。

### 没有数据时怎么显示？

显示「数据不足」，不显示 0 分，避免误解为极差表现。

### 分数下降了先看什么？

先看超期率，再看按期率，最后看平均闭环时长；同时下钻对应任务清单确认原因。
