# ADMIN.md · 管理后台交接规范

> `admin.html` 是 ITO 产品的浅色管理工作台，与深色驾驶舱（`index.html`）并存。本文档只描述后台；大屏设计规范见 [`HANDOFF.md`](HANDOFF.md)。
>
> 标签口径见 [`TAGS.md`](TAGS.md)，指标口径见 [`METRICS.md`](METRICS.md)；两者分别有机器可读版 `tags.csv` / `metrics.csv`。
>
> **2026-11 数据扩容说明**：任务库已扩展为 2026-07 至 2026-11 共 3,524 条主任务，编号统一为 `TS-YYYYMM-####`，任务列表按 11 月→7 月降序、每页 10 条。现有 128 条历史任务保留在 10 月，子任务仍为 222 条；驾驶舱只统计 11 月 698 条。本文中 128 / 342 / 384 / 86 / 89% / 42·33·29·24 等数值为扩容前基线。

## 1. 定位

后台回答的是“事情怎么落地”，不是“当前系统是否健康”：

- 任务如何拆分、派发、审批、接收、执行、闭环；
- 巡检、值班、维保如何排期与留痕；
- 专业组、人员、作业授权如何管理；
- 预警规则、角色权限、成就墙如何配置；
- 所有关键动作如何进入操作日志。

它**不是** CRUD 模板，也不是把驾驶舱改成浅色。视觉上保持暖白纸感、橙色主强调、Apple 式留白与高信息密度。

登录页支持四种演示身份。身份存入 `sessionStorage`，侧边栏与路由由 `permissions` 判断，页面内写操作再叠加角色只读判断，不允许“菜单隐藏但 URL 可进”。

后台业务状态默认写入浏览器 `localStorage` 的本地快照：任务、消息、日志、巡检 / 维保、值班、大修、权限、字典与自定义字段值在刷新后保留；版本或演示日期变化时自动回到初始数据。访问 `admin.html?reset=1` 或点击登录页「重置演示数据」可清空快照、成果物和附件并恢复初始状态。驾驶舱打开时读取同一份快照：站内消息、巡检异常合计、维保计划计数每 10 秒同步，值班排班只在打开驾驶舱时同步一次。

## 4. 数据契约

**日期快照**：`ito-data.js` 以 `2026-11-02 20:56` 为基准快照。页面加载时按系统当天日期计算天数差，把任务截止、消息、日志、值班、巡检、维保、授权有效期整体平移；成员入组时间保持真实历史日期不变。自动演示模式下演示时间跟随系统时钟，超期按当前时间实时判断；使用 `?demo=YYYY-MM-DD` 指定日期时，演示时间固定为 20:56，便于回归测试。跨过午夜后页面会自动刷新。

### 4.2 任务

- 演示数据：128 个主任务、137 个子任务；含审批中、已挂起、已取消、已完成但晚于截止、领导审批待办样例；生成任务覆盖 40 名成员，主管也有执行任务。
- 主状态：`草稿`、`待分发`、`执行中`、`审批中`、`已挂起`、`待汇总`、`审批驳回`、`已完成`、`已取消`。
- 没有“待接收”状态；派发后直接进入执行中。
- 主任务状态由子任务推导：全部完成 → 已完成；有审批中 → 审批中；有已挂起 → 已挂起；有执行中 → 执行中；有待分发 → 待分发；全部草稿 → 草稿；取消任务固定为已取消。
- 领导下发任务完成全部子任务后进入 `待汇总`；负责人汇总报审后进入 `审批中`；领导驳回显示 `审批驳回`，领导通过回到 `已完成`。
- 领导审批不再显示“领导审批中 / 领导审批已挂起 / 领导审批已驳回 / 领导已审批”等附加标签，统一收敛为单个主状态：`待汇总`、`审批中`、`已挂起`、`审批驳回`、`已完成`。
- 负责人审批或领导审批超过 72 小时未处理，统一变为 `已挂起`；重新提交或继续审批后重新计时。
- 任务创建分两种模式：
  - 不拆分：主任务直接填写任务类型、等级、预估工时、执行人、开票、授权、截止时间、标签。
  - 拆分子任务：父任务只填名称、专业组、发起人、负责人、标签与描述；子任务独立填写名称、类型、等级、工时、执行人、开票、授权、截止时间、标签。
- 开票与授权强联动：勾选开票 → 授权必选；不勾选开票 → 授权固定为无需授权。
- 主任务截止时间取全部子任务最晚时间；父任务等级取最高子任务等级；单子任务取该子任务类型，多子任务为综合。
- 任务来源不再由用户选择：发起人选择领导（张维远）时自动记为「领导下发」，发起人为空或选择本人时自动记为主管 / 组长自建。
- 新建任务默认留空：专业组、负责人、发起人、等级、类型、工时、执行人、截止、授权、开票均需手动选择；负责人只能选择主管 / 组长，执行人可以是全员；必填项在字段下方提示。
- 负责人、发起人、执行人使用统一人员选择器：列表显示姓名、岗位、专业组，选中后框内只显示姓名。
- 保存草稿：主 / 子任务状态为草稿，不增加在办、专业组在办、新增任务与趋势；草稿可编辑、删除、继续拆分或派发。
- 草稿派发：校验任务名称、专业组、负责人、至少一个子任务及子任务名称 / 执行人 / 截止时间；通过后子任务转待分发，统计只增加一次。
- 执行人提交成果物后进入审批中，负责人有 72 小时审批窗口；超时自动变为已挂起。
- 已挂起可由执行人重新提交，审批计时从最后一次提交重新计算。
- 负责人驳回后退回执行中，执行人重新完成并再次提交。
- 领导下发任务在负责人审批通过、全部子任务完成后即闭环；闭环后负责人汇总成果物提交领导审批。
- 领导审批独立记录在 `leaderApproval`，但界面状态统一由主状态展示，不再出现“已完成 · 领导审批已挂起”这类双标签。
- 领导驳回父任务后可选择“退回负责人补充汇总”或“重开指定子任务”；补充汇总保持子任务已完成，重开只退回勾选子任务。
- 取消：发起人、负责人可在草稿、待分发、执行中、审批中、已挂起阶段取消；取消不计闭环、不计在办、不计超期；已完成、已取消为终态。
- 编辑任务、改派执行人只允许在草稿、待分发、执行中；审批中、已挂起、已完成、已取消不可编辑或改派。
- 领导层、主管层都可以编辑处于可编辑状态的任务；员工层的「编辑」用于编辑本人已提交成果物，不修改任务信息。
- 执行中改派保留当前任务状态，记录原执行人、新执行人、原因和时间。
- 闭环主任务：在办 −1、已闭环 +1、对应专业组 −1、趋势完成 +1；领导审批不重复改变闭环统计。
- 超期数不写死，由 `isOverdue()` 与 `isLateClosed()` 实时统计；草稿、已取消不参与超期统计。
- 超期是跨状态视图，不是流程状态。任务中心「超期」视图包含两类子任务：
  - 未完成且截止时间早于当前数据快照时间；
  - 已完成但 `completedAt > due`。
- 两类都计入任务中心的「超期」统计；已完成但晚于截止的子任务仍显示「已完成」，不回退状态、不重新打开，并计入已完成 / 闭环。
- 未完成超期按当前演示时间实时计算；基准 20:56 为 7 项，17 点多为 6 项。已完成但晚于截止 2 项，任务中心「超期」合计会随当前时间变化。
- 驾驶舱大屏的「超期」是未完成待处理口径，与任务中心「超期（含晚闭环）」口径不同，不要直接相加或互相覆盖。
- 状态列只显示主状态，不再附加任何超期标签。
- 状态下拉分为「流程状态」与「超期」两个分组，避免把超期误认为流程状态。

### 4.3 值班

- 主页面为周值班表：周次 / 日期范围 / 应急 / 线路 / 网络 / 桌面 / 出勤 / 状态；点击行查看完整值班表。
- 只保留通信组一套人员：通信助理赵宏毅固定为联系人，不参与值班；应急 / 线路 / 网络 / 桌面 4 个角色从通信组 9 人值班池按周轮换；应用组、在线组、基础设施组不参与值班。
- 值班授权按人发放：通信组 10 人（含赵宏毅）持有，其他组不持有；授权矩阵的「值班授权」列按此口径展示。
- 值班手机直接取人员档案中的电话；外协技术助理为外协名册（吴立诚 / 沈望舒 / 韩立言，工程公司），不关联系统档案、不持有值班授权。
- 详情为 Excel 式值班表：岗位 / 代码 / 姓名 / 值班手机，固定 6 行：通信助理、应急、线路、网络、桌面、工程公司项目部通讯技术助理；通信助理行标注联系人，技术助理行标注外协。
- 代码使用 `TX-ZL / TX-YJ / TX-XL / TX-WL / TX-ZM`；外协技术助理代码留空。
- 详情默认只读；仅通信助理本人 / 领导 / 全局管理员点「编辑」后，编辑界面以弹层形式位于详情之上，编辑层内缩，详情四周可见；其他主管与员工只读。
- 导入 / 导出预览同样位于详情上层；导入流程：选择文件 → 解析 → 预览 → 确认进入编辑 → 保存。
- 通信助理本人 / 领导 / 全局管理员可下载模板、导入 CSV / XLSX、保存；值班手机显示完整 11 位号码。
- 模板与导出均为 XLSX，带大标题与周次，导出前先预览。
- 周次、日期随 `meta.today` 自动平移；值班表列表展示**全部 13 周**（前 6 周 + 当前周 + 后 6 周），当前周高亮标注，点击任意周打开该周值班表详情。
- 值班作为常规任务：每周 4 条「通信值班 · 第 N 周 · 角色」，标准工时 8h，覆盖当前周与未来 2 周；往期值班写入历史归档，进入「我的任务」5 个月闭环趋势。
- 待命不计工时；出勤按天计 8h，同一天多次只计一次；每人每周最多 2 天，全组每周 4–6 天。本周只生成今天及以前的出勤，未来日期不提前记完成。
- 周表「出勤」列显示 `N 天 · 8N h`，点击打开只读出勤记录（日期 / 人员 / 岗位 / 事由 / 工时）。
- 详情内不再提供「待交接事项 / 提交交接 / 确认接班」；`week.handover` 仅作为预警规则 R-05 的只读状态，默认本周已完成，不再产生常驻告警。
- 驾驶舱「值班与授权」面板展示通信助理 / 应急 / 线路 / 网络 / 桌面五个角色，整块可下钻到 `#/duty?week=YYYY-MM-DD`，自动展开对应周值班表。
- 员工层演示身份为赵明川（通信组、线路值班、持高风险作业授权与值班授权）。

| 主管层 | 我的任务、任务管理、团队统计、巡检、维保、值班、大修、组织架构、授权、站内消息、属性勋章 | 日常运营读写；可编辑可编辑状态任务；授权只读 |
| 员工层 | 我的任务、个人统计、值班、大修、我的授权、站内消息、属性勋章 | 仅本人任务执行与本人成果物编辑；大修可查看全部，仅本人行动项描述 / 附件 / 进展、本人物资进度 / 计划可编辑，不能新增 / 导出；人员矩阵只读；授权只读 |
| 系统管理员 | 组织架构、属性勋章、字典配置、预警规则、角色权限、操作日志 | 配置中心、组织架构与审计；默认落地字典配置；不参与业务派发审批，不展示个人统计；不提供大修管理与站内消息入口；字典项与字段定义可维护；属性勋章可维护 |
| 全局管理员 | 全部菜单与页面 | 仅本地 DEV 切换器可见；全部模块、全部操作开放，可查看团队与任意员工月报 |

本地右下角提供 DEV 角色切换器：`领导 / 主管 / 员工 / 管理员 / 全局`，在 `file://` 双击离线包、`localhost`、`127.0.0.1`、`::1` 或 `?dev=1` 时启用；登录页始终只显示四角色、不显示 DEV，进入后台后 DEV 才出现，全局管理员也只在后台 DEV 中出现。DEV 切换角色时保留当前页面、查询参数、分页与滚动位置；新角色无权访问当前页面时回到该角色默认页并提示。登录页选择角色则始终进入该角色默认页（领导 / 主管 / 员工 → 我的任务，管理员 → 字典配置）。演示地址建议使用 `admin.html?dev=1&demo=2026-12-01#/tasks`。

权限矩阵为 **4 角色 × 10 模块 = 40 格**，默认开放 **24 格**：

```text
领导 8 + 主管 8 + 员工 5 + 管理员 3 = 24 / 40 = 60%
```

权限矩阵可调整，但：

- 系统管理员列只读，避免把平台锁死；领导层配置中心锁定关闭；
- 领导层可新建、编辑可编辑状态任务；不显示派发、取消、调整；值班可导入 / 保存，组织可新增 / 编辑成员；作业授权可续期 / 撤销，不显示新增授权；
- 员工层“我的授权”只显示本人记录，不显示续期 / 撤销 / 新增 / 导出；
- 领导层不显示操作日志，直接访问 `#/logs` 会被权限拦截；
- 成就墙对员工层只读；主管层、领导层、系统管理员显示新增 / 编辑 / 删除；
- 修改角色权限后侧边栏与路由立即生效。

### 4.5 成果物与附件

**存储**

- 前端验收版使用 IndexedDB，数据库 `ito-deliverables-v3`。
- 对象仓库：`submissions`、`summaries`、`fileMeta`、`fileBlobs`、`workflow`、`leaderWorkflow`、`meta`。
- 成果物 Blob 存在 `fileBlobs`，元数据存在 `fileMeta`；刷新、关页面后仍保留。
- 清除浏览器站点数据会丢失；接后端后替换为对象存储 + 签名 URL。

**数据模型**

```js
sub.submissions = [{
  version: 1,
  note: '成果说明',
  submittedBy: '刘景行',
  submittedAt: '2026-11-03 20:56',
  files: [{ id, name, mime, size, uploadedBy, uploadedAt }]
}]

task.leaderSummary = {
  version: 1,
  note: '汇总说明',
  submittedBy: '刘景行',
  submittedAt: '...',
  files: [...]
}
```

- 提交说明、审批意见、成果物文件分开保存，不共用 `approval.comment`。
- 重新提交生成 `v2`，历史版本保留。
- 任务提交状态与审批结果写入 `workflow` / `leaderWorkflow`，刷新后回放。

**文件与预览**

- 提交成果物、重新提交、领导汇总都要求至少 1 个文件。
- 应用层不设固定大小 / 数量上限，但浏览器配额不足时会提示。
- 支持 PDF、图片、文本、CSV、JSON、Markdown、视频、音频、DOCX、XLSX、PPTX、ZIP。
- Office 预览使用本地 `docx-preview`、SheetJS、`pptx-preview`；ZIP 使用 JSZip。
- 未知格式降级为下载，不显示空白预览。

**预置样例**

`assets/samples/deliverables/` 预置 6 类样例，首次加载自动写入 IndexedDB：

| 任务 | 样例 | 格式 |
| --- | --- | --- |
| `T10026-01` | 需求评审方案.docx | DOCX |
| `T10024-01` | 告警规则梳理报告.pdf | PDF |
| `T10016-01` | 监测数据补录清单.xlsx | XLSX |
| `T10017-01` | 空调滤网清洗照片.png | PNG |
| `T10029-01` | 交换机日志巡检记录.pdf | PDF |
| `T10029` | 核心交换机巡检汇总.pptx + 巡检照片.zip | PPTX / ZIP |

**入口与层级**

- 任务中心列表的操作列提供「查看成果物」按钮，直接打开该任务成果物清单；没有成果物时按钮置灰并提示“暂无成果物”。
- 任务详情抽屉内也显示成果物区块。
- 预览使用独立 `#previewRoot`，z-index 高于任务详情抽屉和成果物清单；关闭预览后回到原界面。

**权限**

- 执行人：本人子任务可上传、编辑已提交成果物、重新提交、查看历史版本。
- 主管层：可预览、下载、审批。
- 领导层：只读预览、下载、领导审批。
- 员工层：只看本人成果物，但可编辑本人已提交的成果物版本。
- 系统管理员：不进入业务成果物。

### 4.6 任务列表操作列

任务中心操作列只保留：

```text
编辑  |  查看成果物
```

- 操作列不固定在右侧，不设置独立白底或阴影，表头和按钮左对齐。
- 任务列表的发起人、负责人与子任务执行人使用角色名签：发起人紫色、负责人橙色、执行人蓝色；不再显示头像块与姓氏首字。
- 派发与审批卡片的人员字段使用同一套角色名签。
- 点击任务行进入任务详情，操作列不再放「详情」按钮。
- `编辑` 始终显示，按角色决定编辑对象：
  - 领导层 / 主管层：编辑任务信息；草稿、待分发、执行中可点，其他状态置灰，提示“当前状态不可编辑”。
  - 员工层：编辑自己已提交的成果物；没有提交记录、待分发、已取消时置灰，提示“暂无可编辑成果物”。
- 员工成果物编辑：
  - 有提交记录且子任务处于执行中、审批中、已挂起、已完成时可点；
  - 弹窗预填当前最新版本文件与成果说明，可追加、移除文件；
  - 保存生成新版本，旧版本保留。
- 员工编辑后的状态处理：

| 子任务状态 | 保存后 |
| --- | --- |
| 审批中 | 替换为最新版本；审批意见清空；审批状态重置为待审批；72 小时重新计时 |
| 已挂起 | 替换为最新版本；回到审批中；审批意见清空；72 小时重新计时 |
| 执行中（有历史提交） | 替换为最新版本；进入审批中；审批意见清空；72 小时重新计时 |
| 已完成 | 保存为补充版本；保持已完成；不重新审批 |

- `查看成果物` 始终显示；没有成果物时置灰，悬停提示“暂无成果物”。
- 状态列只显示主状态，不附加任何超期标签；超期通过顶部「超期」统计和状态下拉里的「超期」视图体现。
- 任务中心「超期」统计同时包含未完成且过截止、已完成但晚于截止的子任务；前者不计完成，后者计入已完成。
- 派发、负责人审批、领导审批、汇总报审统一在「派发与审批」页，不在任务列表重复出现。
- 提交成果 / 重新提交、改派、取消任务、删除草稿保留在任务详情；展开的子任务行只保留详情、提交 / 重新提交、改派与成果物入口。
- 任务详情只展示审批状态、审批人、审批时限和「前往派发与审批」链接，不直接放审批按钮。
- 我的任务保留独立的「成果物」列（显示版本与文件数）；详情通过点击行打开，操作列按状态显示「提交成果 / 重新提交」，已提交成果物的显示「查看成果」。

### 4.7 个人统计 / 运营统计 / 团队统计

「工作台 → 个人统计（领导端为运营统计、主管端为团队统计）」只对领导层、主管层、员工层开放，系统管理员不可见。

- 统计口径：执行人是当前登录人、截止时间在当前月份、未取消的任务。
- 顶部展示个人成就标签，分两段；卡片内容全部居中、同组等高，不显示类型角标与描述：
  - 人员标签：个人能力标签，带 1–3 星；授权关联标签统一显示「授权」，不显示星级；
  - 任务标签：个人完成任务累计，显示完成次数。
- 点击标签卡片打开详情；累计次数、首次领取时间、描述、解锁条件、升星规则只在详情中出现。
- 四项 KPI：当月总任务、已完成、执行中、超期。
- 当月任务表字段：任务名称、任务UID、任务类型、任务等级、预估工时、截止时间、状态；不显示进度。
- 点击任务行进入任务详情。
- 页面分「统计 / 月报」两个标签页；页签与下方内容留 16px 缝隙（`.personal-tabs` 对齐 `.task-tabs` 节奏）；月报直接在页面内预览，不再先点按钮。
- 月报页签顶部为卡片头「月报导出与预览」：标题与筛选下拉同排——筛选框（范围 / 月份 / 专业组 / 人员）紧跟标题右侧、左侧锚定，切到员工月报时「人员」下拉向右追加、已有筛选框位置不动；「下载月报」按钮独立固定在卡片头最右侧（页头右上不放按钮）。卡片头带水平内边距，标题与按钮不贴卡片边缘。
- 月报范围：
  - 员工：我的月报；
  - 主管：我的月报 / 本组月报 / 组员月报；
  - 领导：个人月报（我发起）/ 专业组月报 / 员工月报；
  - 筛选：月份、专业组、人员；主管固定本组，组员月报人员选择器只列本组；领导 / 全局的「员工月报」可选全部 40 人，包含 4 位主管。
  - 只有选择「员工月报」时才显示专业组筛选；专业组默认全部，人员选择器支持搜索、按专业组分组，选中后只显示姓名。
- 月报内容：KPI 四卡对齐统计页签样式（白卡 + 顶部色条，当月任务橙 / 已完成绿 / 进行中蓝 / 超期红）→ 属性勋章（仅个人 / 员工月报显示：人员标签橙渐变卡带星级与首次时间、任务标签蓝卡、授权标签统一显示「授权」且无首次时间；专业组月报不显示勋章）→ 任务明细表；点击「下载月报」先弹出预览，确认后导出 HTML。
- 页内预览区为**固定高度**（`calc(100vh - 292px)`，卡片底边贴视口底、`.page:has(.report-inline-card)` 归零容器底部内边距，DEV 切换器悬浮其上不占位）；预览内月报头部、KPI、勋章与「任务明细」标题固定不动，仅明细表格在预览内部滚动（srcdoc `fixed` 版式，无外围灰边、月报满幅呈现）；「下载月报」导出的 HTML 仍为流式整篇文档，无内部滚动条。

### 4.8 属性勋章

- 位置：一级菜单「属性勋章」，所有角色可见；非管理员不再显示配置中心。
- 内容是系统勋章 / 标签字典，不是员工画像：
  - 左侧人员标签：显示星级与标签说明；实际取得授权后自动增加同名标签，统一显示「授权」；
  - 右侧任务标签：显示名称、类型与说明，不显示完成次数。
- 点击标签卡片打开标签定义；新增 / 编辑弹窗展示完整字段（名称、类型、颜色、解锁条件、2/3 星门槛、说明），并使用宽弹窗。
- 主管 / 领导 / 管理员可新增、编辑、删除；员工只读。
- 人员标签星级规则按标签单独配置：默认 `5 次升 2 星`、`10 次升 3 星`，每个标签可在新增 / 编辑时调整门槛。
- 新建人员标签默认从 1 星开始；新建任务标签不显示星级。
- 人员标签首次领取时间来自“人员第一次获得该标签”的数据；新建标签尚未被领取时显示“尚未领取”。
- 属性勋章页面左右两栏等宽，各按 4 个/行呈现，两栏卡片等高；人员勋章额外显示星级。授权取得的属性勋章统一显示「授权」，不显示星级、取得次数，也不显示首次领取 / 授权取得日期——授权只有「有 / 无」两态。
- 授权关联勋章按「有 / 无授权」两态管理：授权过期或撤销后从人员标签中剔除，重新完成培训、考试、体检并取得授权后自动恢复；不记录首次领取时间。
- 标签颜色在新增 / 编辑时从多色块中选择，也支持自定义色号。
- 鼠标悬停时图标上抬；点击卡片打开标签详情。
- 新增 / 编辑表单字段顺序：标签名称、标签类型、标签颜色、解锁条件、升星门槛（仅人员标签）、标签说明；不显示完成次数、首次领取时间和初始星级。
- 标签详情：
  - 人员标签：名称、类型、解锁条件、当前星级、累计次数、升星规则、首次领取时间；授权关联标签不显示日期行，展示「授权」标识与「取得授权后自动获得」规则；
  - 任务标签：名称、类型、解锁条件、完成次数，不显示星级和首次领取时间。
- 新增 / 编辑 / 删除：系统管理员、主管、领导可见；员工只读。
- 标签改名 / 删除会同步更新任务、子任务、人员成就与任务标签元数据；任务表单的标签选择器动态读取当前标签字典，新增 / 改名 / 删除后立即生效。
- 同类型下不允许重名标签；改名时若与同类型标签重名，字段下方提示「同类型标签名称已存在」。
- 预警规则、角色权限不再有页内 Tab；属性勋章为一级菜单。

### 4.9 通知

- 位置：顶栏下方右上角，最多同时显示 2 条；单次展示 6 秒后自动收起，移动端同步回到顶部浮层。
- 样式：白色卡片、3px `#EB612A` 左条、橙色图标与倒计时进度条。
- 进入界面时优先显示未读站内消息，最近 1–2 条。
- 6 秒自动收起，卡片文字为**动态数字倒数**（6→1，hover 暂停时显示「已暂停」）；鼠标悬停暂停计时；支持手动关闭；点击跳转对应页面。
- 任务动作会按人员排队推送：

| 动作 | 通知对象 |
| --- | --- |
| 派发 | 执行人 |
| 提交成果 | 负责人 |
| 审批通过 / 驳回 | 执行人 |
| 重新提交 | 负责人 |
| 汇总报审 | 领导 |
| 领导审批通过 / 驳回 | 负责人 |
| 改派 | 原执行人 + 新执行人 |
| 取消 | 执行人 + 负责人 |

- 目标人员不是当前登录人时，通知进入队列；切换到对应角色后补弹。
- 通知不在页面刷新后保留，属于当前演示会话。

### 4.10 组织架构

- 顶部显示整体满配 50 / 目前 40（80%）；每组满配 13 / 13 / 12 / 12，目前各 10 人。**应用组专业组色为酒红 #9F2936**（2026-11-08 调整，原品牌橙与图表卡总口径进度条撞色；品牌橙保留给总口径进度条与品牌元素）。
- 组卡只展示主管、组长、目前 / 满配与满编率，不展示在办与超期任务。
- 左侧为近 6 个月人员变动折线图，底部显示当前 / 满配与满编率（随筛选与成员数量变化实时更新：筛选后为对应专业组口径，新增 / 调组成员后当前月点位与底部计数联动；四组历史序列已错开可辨；进度条与百分比颜色未筛选为中性色、筛选后为对应专业组色）；点击专业组后只显示该组折线，tooltip 显示专业组、月份、人数。
- 成员名录包含 4 位主管、4 位组长和 32 名工程师，列（成员 / 专业组 / 角色 / 标签 / 入组，无岗位列）；角色列以三色 chip 标识（主管橙红 / 组长紫 / 成员绿）；名录右上恒显当前范围（未筛选「全部专业组」、筛选后为组名），不重复主管 / 组长信息（选中专业组卡片即展示其主管与组长）；按「专业组 → 主管 → 组长 → 成员 → 入组时间」排序，新增成员排在本组末尾。
- 成员档案只保留专业组、主管、组长、角色、能力标签、成就标签、作业授权，以及创建 / 最近更新 / 操作记录，不展示任务。
- 组织架构不涉及任务数据。

### 4.16 预警规则

- 规则字段：编号 / 规则名称 / 触发条件 / 状态 / 创建时间 / 更新时间 / 操作；创建与更新时间是正式列，不再作为名称下的辅助小字；名称列与表头左对齐，其余列居中；「最近触发」不放在表格，移到点击规则行打开的详情弹窗。
- 规则详情：基本信息（类型 / 阈值 / 条件 / 范围 / 渠道 / 去重）、记录信息（创建 / 更新 / 操作人）、触发概览（累计次数、最近触发、最近命中数）、最近命中明细（最多 6 个对象，显示名称 + 编号）；不再展示逐次触发时间线。
- 规则结构：`type / threshold / unit / scope / severity / dedupeMinutes / enabled / lastFiredAt / dedupeUntil / fireCount / lastSignature / lastHitCount / lastHits / createdAt / createdBy / updatedAt / updatedBy`；`condition` 由类型与阈值生成，编辑表单中只读展示；模拟历史按规则预置 3–5 次，最新一次保留命中对象，并同步写入操作日志。
- 五类规则全部接入真实判定：任务超期（子任务未完成且超期超过阈值）、审批超时（待审批超过阈值）、巡检异常（近 7 天异常项达到阈值）、SLA 达成率（低于阈值）、值班交接超时（周一 08:00 + 阈值分钟仍未确认）。
- 执行时机：进入后台时检测一次、每 60 秒轮询一次、任务 / 审批 / 巡检 / 值班等业务动作写日志后触发一次；规则页提供「立即检测」。
- 命中后写入站内消息与操作日志，并回写 `lastFiredAt`、`fireCount`、`lastSignature`；同一对象 30 分钟内命中相同规则只通知一次，命中对象集合变化时重新通知。
- 规则表单：名称、类型、阈值（带单位提示）、只读触发条件、通知范围、状态；编辑时追加只读的创建时间与更新时间。
- 演示边界：纯前端环境只生成站内消息与日志，不发送短信、邮件或企业微信。

| 新建任务 | 领导层、主管层可新建；新建字段默认留空，必填项字段下方提示；发起人选择领导时来源自动为「领导下发」，为空或本人时自动为自建；负责人只选主管 / 组长；可选择“保存草稿”或“创建并派发” |

| 负责人审批驳回 | 子任务退回执行中，执行人重新完成并再次提交 |

| 编辑成果物 | 员工对本人已提交成果物追加、移除文件或修改说明；审批中/已挂起/执行中保存后重置审批计时并清空原审批意见；已完成保存为补充版本，不重新审批 |

| 汇总报审 | 领导下发任务闭环后，负责人至少上传 1 个汇总附件并提交领导审批；领导可在线预览 |

## 9. 已知边界

- 演示数据为模拟数据，不代表真实生产指标。
- 员工身份固定为赵明川；其他员工的任务无法在四人演示身份中直接操作，主管可代为派发与审批，但提交成果只对执行人开放。
- 月报为前端生成的 HTML 文件，不是服务端报表。
- 成果物存 IndexedDB，清浏览器站点数据会丢失；不设应用层大小上限，但浏览器磁盘配额仍可能写入失败。
- Office 预览由本地库渲染，复杂版式可能与原文件存在差异；渲染失败会降级为下载。
- 预置样例只在首次加载或数据库重置后写入，不会覆盖用户新上传的文件。
- 权限矩阵与成果物可见性只控制前端，不构成真实安全边界；接后端后必须用服务端鉴权、对象存储签名 URL 与审计。
