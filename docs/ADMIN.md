# ADMIN.md · 管理后台交接规范

> `admin.html` 是 ITO 产品的浅色管理工作台，与深色驾驶舱（`index.html`）并存。本文档只描述后台；大屏设计规范见 [`HANDOFF.md`](HANDOFF.md)。

## 1. 定位

后台回答的是“事情怎么落地”，不是“当前系统是否健康”：

- 任务如何拆分、派发、审批、接收、执行、闭环；
- 巡检、值班、维保如何排期与留痕；
- 专业组、人员、作业授权如何管理；
- 预警规则、角色权限、成就标签如何配置；
- 所有关键动作如何进入操作日志。

它**不是** CRUD 模板，也不是把驾驶舱改成浅色。视觉上保持暖白纸感、橙色主强调、Apple 式留白与高信息密度。

## 3. 路由与身份

哈希路由：

| 路由 | 页面 | 权限键 |
| --- | --- | --- |
| `#/dashboard` | 运维驾驶舱 | `dashboard` |
| `#/tasks` | 任务中心 | `task` |
| `#/dispatch` | 派发与审批 | `task` + 领导 / 主管 |
| `#/mine` | 我的任务 | `task`，侧边栏仅员工可见 |
| `#/inspection` | 巡检管理 | `inspect` |
| `#/duty` | 值班管理 | `duty` |
| `#/maintenance` | 维保管理 | `maintain` |
| `#/groups` | 专业组 | `group` |
| `#/auth` | 作业授权 | `auth` |
| `#/messages` | 消息中心 | `message` |
| `#/alerts` | 预警规则 | `config` |
| `#/roles` | 角色权限 | 仅系统管理员 |
| `#/tags` | 成就标签 | `config` |
| `#/logs` | 操作日志 | 领导 / 系统管理员 |

登录页支持四种演示身份。身份存入 `sessionStorage`，侧边栏、页面与按钮均由 `permissions` 实时判断，不允许“菜单隐藏但 URL 可进”。

支持直接链接：

```text
admin.html?role=manager#/dispatch
admin.html?role=leader&still=1#/dashboard
```

`role` 仅用于演示 / 截图；`still=1` 关闭入场与过渡动效。

## 4. 数据契约

**日期快照**：`ito-data.js` 以 `2026-11-02 20:56` 为基准快照。页面加载时按系统当天日期计算天数差，把任务截止、消息、日志、值班、巡检、维保、授权有效期整体平移；成员入组时间保持真实历史日期不变。演示时间固定为当天 20:56，因此超期数量稳定为 7。跨过午夜后页面会自动刷新。可用 `?demo=YYYY-MM-DD` 指定日期做回归测试，此时不会自动刷新。

### 4.1 总览

| 指标 | 值 | 说明 |
| --- | --- | --- |
| 在办任务 | 128 | 期初 86 + 新增 384 − 完成 342 |
| 近 30 天闭环 | 342 | 与趋势末 30 天合计一致 |
| 超期 | 7 | 由子任务截止时间实时计算 |
| 任务 SLA | 96.2% | 与驾驶舱的“服务 SLA 99.972%”口径不同，不要合并 |
| 按期闭环率 | 89.0% | 近 30 天 |
| 专业组在办 | 42 / 33 / 29 / 24 | 合计 128 |

### 4.2 任务

- 12 个主任务，20 个子任务；其中恰好 7 个超期子任务。
- 子任务状态：`草稿`、`待派发`、`待审批`、`待接收`、`执行中`、`已完成`。
- 主任务状态由子任务推导：全部完成 → 已完成；有执行中 → 执行中；否则按待审批 > 待派发 > 待接收；草稿任务固定为草稿。
- 主任务进度 = 可见子任务进度均值；员工视角只统计自己的子任务。
- 新建任务：写入列表、在办 +1、对应专业组 +1、新增 +1、趋势末项 +1。
- 新建任务支持主任务与子任务拆分：任务来源（领导下发 / 主管自建）、发起人、负责人、主任务标签、子任务名称 / 类型 / 预估工时 / 执行人 / 授权 / 开票 / 截止时间 / 标签。
- 任务标签多选且不限数量；子任务标签同样多选；“需要开票”按子任务独立勾选。
- 发起人规则：领导下发时关联领导（默认张总）；主管自建时为主管本人，主管可同时担任发起人、负责人、执行人。
- 主任务截止时间取全部子任务最晚截止时间；单子任务取该子任务类型，多子任务类型为“综合”。
- 保存草稿：主 / 子任务状态为草稿，不增加在办、专业组在办、新增任务与趋势；草稿出现在任务中心“草稿”筛选，可继续编辑、拆分、派发或删除。
- 草稿派发：校验任务名称、专业组、负责人、至少一个子任务及子任务名称 / 执行人 / 截止时间；通过后子任务转待派发，统计只增加一次。
- 闭环主任务：在办 −1、已闭环 +1、对应专业组 −1、趋势完成 +1。
- 超期数不写死，由 `isOverdue()` 实时统计；草稿不参与超期统计。

### 4.3 角色

| 角色 | 默认可见 |
| --- | --- |
| 领导层 | 除角色权限外的全部模块 + 操作日志 |
| 主管层 | 驾驶舱、任务、派发审批、巡检、值班、维保、专业组、授权、消息 |
| 员工层 | 驾驶舱、任务、我的任务、值班、授权、消息 |
| 系统管理员 | 驾驶舱、专业组、授权、消息、预警规则、角色权限、标签、日志 |

权限矩阵可调整，但：

- 驾驶舱入口对所有角色强制保留；
- 系统管理员列只读，避免把平台锁死；
- 修改角色权限后侧边栏与路由立即生效。

## 5. 关键交互

| 动作 | 结果 |
| --- | --- |
| 新建任务 | 打开创建弹窗，填写主任务、来源、发起人、标签并拆分子任务；可选择“保存草稿”或“创建并派发” |
| 保存草稿 | 生成 `T100xx` 但状态为草稿，不改变在办 / 超期 / 趋势；任务中心草稿筛选可编辑、删除、再次派发 |
| 创建并派发 | 生成主任务与 `T100xx-01…` 子任务，进入待派发，在办 +1、专业组 +1、新增 +1、趋势末项 +1 |
| 派发 | 选择组内负责人、截止时间、作业授权，状态转待接收 |
| 审批通过 | 状态转待接收，写审批日志 |
| 审批驳回 | 状态退回待派发，保留审批意见 |
| 接收 | 状态转执行中，进度至少 5% |
| 提交进度 | 可多次提交；100% 时子任务闭环，全部子任务完成则主任务闭环 |
| 巡检“异常” | 新增巡检记录并自动生成整改任务，进入待派发 |
| 值班格 | 点击打开当天排班编辑，保存后整表刷新 |
| 维保登记 | 新增记录并顺延下次执行时间 |
| 授权续期 | 更新有效期与状态；撤销需二次确认 |
| 消息 | 点击即已读并打开详情；可标为未读、全部已读、跳转处理页面 |
| 规则 | 启停、新增、编辑、删除；删除需二次确认 |
| 导出 | 任务、巡检、维保、授权、日志、月报均真实下载本地文件 |
| 全局搜索 | 回车跳转任务中心并按关键字过滤（员工只搜自己的任务） |

所有弹窗支持 `Esc` 关闭、点击遮罩关闭；提交前做必填校验；不允许假按钮。

## 6. 视觉令牌

后台与驾驶舱是两套视觉体系，只共享品牌与数据。

| 令牌 | 值 |
| --- | --- |
| 背景 | `#F5F4F2` 暖白，叠加极轻径向暖色与点阵 |
| 主强调 | `#EB612A` 橙色；深色 `#CF4B18` |
| 文本 | `#1D1D1F` / `#4A4A4F` / `#6E6E73` / `#8A8A8E` |
| 成功 | `#1FAE5C` |
| 告警 | `#C77A00` |
| 严重 / 危险 | `#E5484D` |
| 变更 / 待接收 | `#7A5AF8` |
| 信息 | `#0A72E8` |
| 圆角 | 卡片 18px、弹层 20px、按钮 9px |
| 字体 | 系统 SF / PingFang / 微软雅黑；数字启用 tabular |
| 阴影 | 极轻双层阴影，不使用悬浮霓虹或重玻璃拟态 |

侧边栏 258px；页面最大宽度 1560px；顶栏 72px；页面内边距 28–32px。1600 以下内容自适应，1024 以下侧边栏转为抽屉。

## 7. 状态与刷新

当前为纯前端演示：

- 所有数据从 `ito-data.js` 深拷贝到 `ITO.state`，修改只存在内存；
- 刷新页面回到初始快照；`sessionStorage` 只记住身份；
- 没有网络请求、没有持久化、没有真实鉴权；
- 接真实接口时，把页面提交回调中的“修改 state”替换为 API 调用，成功后再刷新 state。

- [ ] 控制台无错误。
- [ ] 四种身份切换后菜单、路由、按钮权限一致。
- [ ] 新建任务后：任务数 +1、在办 +1、专业组 +1、趋势末项 +1。
- [ ] 新建弹窗包含来源 / 发起人 / 标签 / 子任务拆分 / 授权 / 开票 / 执行人 / 工时；领导任务发起人关联领导，主管自建发起人为本人。

- [ ] 任务清单显示发起人 / 授权 / 标签；详情抽屉显示来源、发起人、标签、授权汇总、开票需求与子任务字段。
- [ ] 派发、审批、接收、提交、闭环全链路可走通。
- [ ] 巡检异常会生成整改任务，任务中心可查到。
- [ ] 值班调整、维保登记、授权续期 / 撤销、消息已读、规则启停、权限调整均生效。
- [ ] 所有导出按钮均下载真实文件。
- [ ] 大屏顶栏「管理后台」、后台「驾驶舱大屏」可互相跳转。
- [ ] `admin.html?role=leader&still=1#/dashboard` 可直接作为静态预览。

## 9. 已知边界

- 演示数据为模拟数据，不代表真实生产指标。
- 员工身份固定为李工；其他员工的任务无法在四人演示身份中直接操作，主管可代接收，但代提交只对本人开放。
- 月报为前端生成的 HTML 文件，不是服务端报表。
- 权限矩阵只控制前端可见性，不构成真实安全边界。
