# ADMIN.md · 管理后台交接规范

> `admin.html` 是 ITO 产品的浅色管理工作台，与深色驾驶舱（`index.html`）并存。本文档只描述后台；大屏设计规范见 [`HANDOFF.md`](HANDOFF.md)。
>
> 标签口径见 [`TAGS.md`](TAGS.md)，指标口径见 [`METRICS.md`](METRICS.md)；两者分别有机器可读版 `tags.csv` / `metrics.csv`。

## 1. 定位

后台回答的是“事情怎么落地”，不是“当前系统是否健康”：

- 任务如何拆分、派发、审批、接收、执行、闭环；
- 巡检、值班、维保如何排期与留痕；
- 专业组、人员、作业授权如何管理；
- 预警规则、角色权限、成就墙如何配置；
- 所有关键动作如何进入操作日志。

它**不是** CRUD 模板，也不是把驾驶舱改成浅色。视觉上保持暖白纸感、橙色主强调、Apple 式留白与高信息密度。

| `#/roles` | 角色权限 | 仅系统管理员 |

登录页支持四种演示身份。身份存入 `sessionStorage`，侧边栏与路由由 `permissions` 判断，页面内写操作再叠加角色只读判断，不允许“菜单隐藏但 URL 可进”。

默认落地页：

| 角色 | 默认路由 |
| --- | --- |
| 领导层 | `#/mine` 我的任务 |
| 主管层 | `#/mine` 我的任务 |
| 员工层 | `#/mine` 我的任务 |
| 全局管理员 | `#/mine` 我的任务 |
| 系统管理员 | `#/roles` 角色权限 |

支持直接链接：

```text
admin.html?role=manager#/dispatch
admin.html?role=leader&still=1#/dispatch
admin.html?role=employee&still=1#/personal
```

`role` 仅用于演示 / 截图；`still=1` 关闭入场与过渡动效。

## 4. 数据契约

**日期快照**：`ito-data.js` 以 `2026-11-02 20:56` 为基准快照。页面加载时按系统当天日期计算天数差，把任务截止、消息、日志、值班、巡检、维保、授权有效期整体平移；成员入组时间保持真实历史日期不变。数据快照时间固定为当天 20:56（内部口径，界面不展示），因此超期数量稳定为 7。跨过午夜后页面会自动刷新。可用 `?demo=YYYY-MM-DD` 指定日期做回归测试，此时不会自动刷新。

### 4.2 任务

- 演示数据：128 个主任务、137 个子任务；含审批中、已挂起、已取消、已完成但晚于截止、领导审批待办样例；生成任务覆盖 40 名成员，主管也有执行任务。
- 主状态：`草稿`、`待分发`、`执行中`、`审批中`、`已挂起`、`待汇总`、`审批驳回`、`已完成`、`已取消`。
- 没有“待接收”状态；派发后直接进入执行中。
- 主任务状态由子任务推导：全部完成 → 已完成；有审批中 → 审批中；有已挂起 → 已挂起；有执行中 → 执行中；有待分发 → 待分发；全部草稿 → 草稿；取消任务固定为已取消。
- 领导下发任务完成全部子任务后进入 `待汇总`；负责人汇总报审后进入 `审批中`；领导驳回显示 `审批驳回`，领导通过回到 `已完成`。
- 领导审批不再显示“领导审批中 / 领导审批已挂起 / 领导审批已驳回 / 领导已审批”等附加标签，统一收敛为单个主状态：`待汇总`、`审批中`、`已挂起`、`审批驳回`、`已完成`。
- 负责人审批或领导审批超过 72 小时未处理，统一变为 `已挂起`；重新提交或继续审批后重新计时。
- 任务创建分两种模式：
  - 不拆分：主任务直接填写任务类型、等级、预估工时、执行人、开票、授权、截止时间、标签。
  - 拆分子任务：父任务只填名称、专业组、发起人、负责人、标签与描述；子任务独立填写名称、类型、等级、工时、执行人、开票、授权、截止时间、标签。
- 开票与授权强联动：勾选开票 → 授权必选；不勾选开票 → 授权固定为无需授权。
- 主任务截止时间取全部子任务最晚时间；父任务等级取最高子任务等级；单子任务取该子任务类型，多子任务为综合。
- 任务来源不再由用户选择：发起人选择领导（张总）时自动记为「领导下发」，发起人为空或选择本人时自动记为主管 / 组长自建。
- 新建任务默认留空：专业组、负责人、发起人、等级、类型、工时、执行人、截止、授权、开票均需手动选择；负责人只能选择主管 / 组长，执行人可以是全员；必填项在字段下方提示。
- 负责人、发起人、执行人使用统一人员选择器：列表显示姓名、岗位、专业组，选中后框内只显示姓名。
- 保存草稿：主 / 子任务状态为草稿，不增加在办、专业组在办、新增任务与趋势；草稿可编辑、删除、继续拆分或派发。
- 草稿派发：校验任务名称、专业组、负责人、至少一个子任务及子任务名称 / 执行人 / 截止时间；通过后子任务转待分发，统计只增加一次。
- 执行人提交成果物后进入审批中，负责人有 72 小时审批窗口；超时自动变为已挂起。
- 已挂起可由执行人重新提交，审批计时从最后一次提交重新计算。
- 负责人驳回后退回执行中，执行人重新完成并再次提交。
- 领导下发任务在负责人审批通过、全部子任务完成后即闭环；闭环后负责人汇总成果物提交领导审批。
- 领导审批独立记录在 `leaderApproval`，但界面状态统一由主状态展示，不再出现“已完成 · 领导审批已挂起”这类双标签。
- 领导驳回父任务后可选择“退回负责人补充汇总”或“重开指定子任务”；补充汇总保持子任务已完成，重开只退回勾选子任务。
- 取消：发起人、负责人可在草稿、待分发、执行中、审批中、已挂起阶段取消；取消不计闭环、不计在办、不计超期；已完成、已取消为终态。
- 编辑任务、改派执行人只允许在草稿、待分发、执行中；审批中、已挂起、已完成、已取消不可编辑或改派。
- 领导层、主管层都可以编辑处于可编辑状态的任务；员工层的「编辑」用于编辑本人已提交成果物，不修改任务信息。
- 执行中改派保留当前任务状态，记录原执行人、新执行人、原因和时间。
- 闭环主任务：在办 −1、已闭环 +1、对应专业组 −1、趋势完成 +1；领导审批不重复改变闭环统计。
- 超期数不写死，由 `isOverdue()` 与 `isLateClosed()` 实时统计；草稿、已取消不参与超期统计。
- 超期是跨状态视图，不是流程状态。任务中心「超期」视图包含两类子任务：
  - 未完成且截止时间早于当前数据快照时间；
  - 已完成但 `completedAt > due`。
- 两类都计入任务中心的「超期」统计；已完成但晚于截止的子任务仍显示「已完成」，不回退状态、不重新打开，并计入已完成 / 闭环。
- 当前演示数据中，未完成超期 7 项、已完成但晚于截止 2 项，任务中心「超期」合计 9 项。
- 驾驶舱大屏的「超期 7」是未完成待处理口径，与任务中心「超期 9」口径不同，不要直接相加或互相覆盖。
- 状态列只显示主状态，不再附加任何超期标签。
- 状态下拉分为「流程状态」与「超期」两个分组，避免把超期误认为流程状态。

### 4.3 值班

- 主页面为周值班表：周次 / 日期范围 / 通信助理 / 值班电话 / 状态；点击行查看完整值班表。
- 通信助理 = 对应专业组主管；状态为正常 / 异常。
- 详情为 Excel 式值班表：岗位 / 代码 / 姓名 / 值班手机，固定 6 行：通信助理、应急、线路、网络、桌面、工程公司项目部通讯技术助理。
- 代码使用 `TX-ZL / TX-YJ / TX-XL / TX-WL / TX-ZM`；工程公司项目部通讯技术助理为外部人员，代码留空。
- 详情默认只读；主管 / 领导 / 管理员点「编辑」后，编辑界面以弹层形式位于详情之上，编辑层内缩，详情四周可见；员工只读。
- 导入 / 导出预览同样位于详情上层；导入流程：选择文件 → 解析 → 预览 → 确认进入编辑 → 保存。
- 主管 / 领导 / 管理员可下载模板、导入 CSV / XLSX、保存；值班手机显示完整 11 位号码。
- 模板与导出均为 XLSX，带大标题与周次，导出前先预览。
- 周次、日期随 `meta.today` 自动平移。
- 值班交接以班次进入任务台账常规区：每周排班生成一条「值班排班 · 第 N 周」，执行人为本周值班人，截止时间为下周一 08:00。
- 交接流转为「待提交 → 待接班确认 → 已完成」；接班人由下一周排班自动带出。
- 交班人在「我的任务」页填写交接记录并提交；接班人在同一页确认接班后班次完成。
- 任务台账常规区展开班次行，可查看交接记录全文与交接人 / 接班人姓名、提交 / 确认时间。
- 交接记录保存在当前演示会话内存中，刷新后回到初始快照。
- 交接卡在员工「我的任务」页，内置「演示值班身份」切换器，可模拟任意轮值成员完成提交与确认；切换身份会整页重载并重置会话，因此主管会话的台账班次行始终是初始状态——跨角色查看交接记录受演示会话隔离限制，属既定演示行为。

### 4.4 角色

| 角色 | 默认可见 | 写入范围 |
| --- | --- | --- |
| 领导层 | 我的任务、任务管理、个人统计、巡检、维保、值班、大修、组织架构、授权、站内消息、属性勋章 | 领导审批；可新建 / 编辑任务；值班可导入/保存；组织可新增/编辑成员；授权只读 |
| 主管层 | 我的任务、任务管理、个人统计、巡检、维保、值班、大修、组织架构、授权、站内消息、属性勋章 | 日常运营读写；可编辑可编辑状态任务；授权只读 |
| 员工层 | 我的任务、个人统计、值班、大修、我的授权、站内消息、属性勋章 | 仅本人任务执行与本人成果物编辑；授权只读 |
| 系统管理员 | 组织架构、站内消息、预警规则、角色权限、属性勋章、操作日志 | 配置中心、组织架构与审计；不参与业务派发审批，不展示个人统计；属性勋章可维护 |
| 全局管理员 | 全部菜单与页面 | 仅本地 DEV 切换器可见；全部模块、全部操作开放，可查看团队与任意员工月报 |

本地右下角提供 DEV 角色切换器：`领导 / 主管 / 员工 / 管理员 / 全局`，仅在 `localhost`、`127.0.0.1`、`::1` 或 `?dev=1` 时显示；登录页保持四角色，不出现全局管理员。

权限矩阵为 **4 角色 × 8 模块 = 32 格**，默认开放 **21 格**：

```text
领导 7 + 主管 7 + 员工 4 + 管理员 3 = 21 / 32 = 65.6%
```

权限矩阵可调整，但：

- 系统管理员列只读，避免把平台锁死；领导层配置中心锁定关闭；
- 领导层可新建、编辑可编辑状态任务；不显示派发、取消、调整；值班可导入 / 保存，组织可新增 / 编辑成员；作业授权可续期 / 撤销，不显示新增授权；
- 员工层“我的授权”只显示本人记录，不显示续期 / 撤销 / 新增 / 导出；
- 领导层不显示操作日志，直接访问 `#/logs` 会被权限拦截；
- 成就墙对员工层只读；主管层、领导层、系统管理员显示新增 / 编辑 / 删除；
- 修改角色权限后侧边栏与路由立即生效。

### 4.5 成果物与附件

**存储**

- 前端验收版使用 IndexedDB，数据库 `ito-deliverables-v3`。
- 对象仓库：`submissions`、`summaries`、`fileMeta`、`fileBlobs`、`workflow`、`leaderWorkflow`、`meta`。
- 成果物 Blob 存在 `fileBlobs`，元数据存在 `fileMeta`；刷新、关页面后仍保留。
- 清除浏览器站点数据会丢失；接后端后替换为对象存储 + 签名 URL。

**数据模型**

```js
sub.submissions = [{
  version: 1,
  note: '成果说明',
  submittedBy: '刘工',
  submittedAt: '2026-11-03 20:56',
  files: [{ id, name, mime, size, uploadedBy, uploadedAt }]
}]

task.leaderSummary = {
  version: 1,
  note: '汇总说明',
  submittedBy: '刘工',
  submittedAt: '...',
  files: [...]
}
```

- 提交说明、审批意见、成果物文件分开保存，不共用 `approval.comment`。
- 重新提交生成 `v2`，历史版本保留。
- 任务提交状态与审批结果写入 `workflow` / `leaderWorkflow`，刷新后回放。

**文件与预览**

- 提交成果物、重新提交、领导汇总都要求至少 1 个文件。
- 应用层不设固定大小 / 数量上限，但浏览器配额不足时会提示。
- 支持 PDF、图片、文本、CSV、JSON、Markdown、视频、音频、DOCX、XLSX、PPTX、ZIP。
- Office 预览使用本地 `docx-preview`、SheetJS、`pptx-preview`；ZIP 使用 JSZip。
- 未知格式降级为下载，不显示空白预览。

**入口与层级**

- 任务中心列表的操作列提供「查看成果物」按钮，直接打开该任务成果物清单；没有成果物时按钮置灰并提示“暂无成果物”。
- 任务详情抽屉内也显示成果物区块。
- 预览使用独立 `#previewRoot`，z-index 高于任务详情抽屉和成果物清单；关闭预览后回到原界面。

**权限**

- 执行人：本人子任务可上传、编辑已提交成果物、重新提交、查看历史版本。
- 主管层：可预览、下载、审批。
- 领导层：只读预览、下载、领导审批。
- 员工层：只看本人成果物，但可编辑本人已提交的成果物版本。
- 系统管理员：不进入业务成果物。

### 4.6 任务列表操作列

任务中心操作列只保留：

```text
编辑  |  查看成果物
```

- 操作列不固定在右侧，不设置独立白底或阴影，表头和按钮左对齐。
- 任务列表的发起人、负责人与子任务执行人使用角色名签：发起人紫色、负责人橙色、执行人蓝色；不再显示头像块与姓氏首字。
- 派发与审批卡片的人员字段使用同一套角色名签。
- 点击任务行进入任务详情，操作列不再放「详情」按钮。
- `编辑` 始终显示，按角色决定编辑对象：
  - 领导层 / 主管层：编辑任务信息；草稿、待分发、执行中可点，其他状态置灰，提示“当前状态不可编辑”。
  - 员工层：编辑自己已提交的成果物；没有提交记录、待分发、已取消时置灰，提示“暂无可编辑成果物”。
- 员工成果物编辑：
  - 有提交记录且子任务处于执行中、审批中、已挂起、已完成时可点；
  - 弹窗预填当前最新版本文件与成果说明，可追加、移除文件；
  - 保存生成新版本，旧版本保留。
- 员工编辑后的状态处理：

| 子任务状态 | 保存后 |
| --- | --- |
| 审批中 | 替换为最新版本；审批意见清空；审批状态重置为待审批；72 小时重新计时 |
| 已挂起 | 替换为最新版本；回到审批中；审批意见清空；72 小时重新计时 |
| 执行中（有历史提交） | 替换为最新版本；进入审批中；审批意见清空；72 小时重新计时 |
| 已完成 | 保存为补充版本；保持已完成；不重新审批 |

- `查看成果物` 始终显示；没有成果物时置灰，悬停提示“暂无成果物”。
- 状态列只显示主状态，不附加任何超期标签；超期通过顶部「超期」统计和状态下拉里的「超期」视图体现。
- 任务中心「超期」统计同时包含未完成且过截止、已完成但晚于截止的子任务；前者不计完成，后者计入已完成。
- 派发、负责人审批、领导审批、汇总报审统一在「派发与审批」页，不在任务列表重复出现。
- 提交成果 / 重新提交、改派、取消任务、删除草稿保留在任务详情；展开的子任务行只保留详情、提交 / 重新提交、改派与成果物入口。
- 任务详情只展示审批状态、审批人、审批时限和「前往派发与审批」链接，不直接放审批按钮。
- 我的任务保留独立的「成果物」列，操作列固定为「详情 → 提交成果 / 重新提交」。

  - 人员标签：个人能力标签，带 1–3 星；

- 点击任务行进入任务详情。
- 页面分「统计 / 月报」两个标签页；月报直接在页面内预览，不再先点按钮。
- 月报范围：
  - 员工：我的月报；

- 月报内容包含 KPI、人员标签与任务明细；点击「下载月报」先弹出预览，确认后导出 HTML。

### 4.8 属性勋章

- 位置：一级菜单「属性勋章」，所有角色可见；非管理员不再显示配置中心。
- 内容是系统勋章 / 标签字典，不是员工画像：
  - 左侧人员标签：显示全 3 星、类型与标签说明；实际取得授权后自动增加同名勋章；
  - 右侧任务标签：显示名称、类型与说明，不显示完成次数。
- 点击标签卡片打开标签定义；新增 / 编辑弹窗展示完整字段（名称、类型、颜色、解锁条件、2/3 星门槛、说明），并使用宽弹窗。
- 主管 / 领导 / 管理员可新增、编辑、删除；员工只读。
- 人员标签星级规则按标签单独配置：默认 `5 次升 2 星`、`10 次升 3 星`，每个标签可在新增 / 编辑时调整门槛。
- 新建人员标签默认从 1 星开始；新建任务标签不显示星级。
- 人员标签首次领取时间来自“人员第一次获得该标签”的数据；新建标签尚未被领取时显示“尚未领取”。
- 属性勋章页面左右两栏等宽，各按 4 个/行呈现，两栏卡片等高；人员勋章额外显示星级。授权取得的属性勋章默认 3 星，不显示取得次数，也不显示首次领取 / 授权取得日期——授权只有「有 / 无」两态。
- 授权关联勋章按「有 / 无授权」两态管理：授权过期或撤销后从人员标签中剔除，重新完成培训、考试、体检并取得授权后自动恢复；不记录首次领取时间。
- 标签颜色在新增 / 编辑时从多色块中选择，也支持自定义色号。
- 鼠标悬停时图标上抬；点击卡片打开标签详情。
- 新增 / 编辑表单字段顺序：标签名称、标签类型、标签颜色、解锁条件、升星门槛（仅人员标签）、标签说明；不显示完成次数、首次领取时间和初始星级。
- 标签详情：
  - 人员标签：名称、类型、解锁条件、当前星级、累计次数、升星规则、首次领取时间；授权关联勋章不显示日期行，仅显示「取得授权即默认 3 星」规则；
  - 任务标签：名称、类型、解锁条件、完成次数，不显示星级和首次领取时间。
- 新增 / 编辑 / 删除：系统管理员、主管、领导可见；员工只读。
- 标签改名 / 删除会同步更新任务、子任务、人员成就与任务标签元数据；任务表单的标签选择器动态读取当前标签字典，新增 / 改名 / 删除后立即生效。
- 同类型下不允许重名标签；改名时若与同类型标签重名，字段下方提示「同类型标签名称已存在」。
- 预警规则、角色权限不再有页内 Tab；属性勋章为一级菜单。

### 4.11 作业授权与审计

- 作业授权为只读矩阵：12 列，基础资格（值班授权 / 入厂授权 / 基本安全培训）+ 作业授权（工作负责人 / 准备工程师 / 高风险 / RP1 / RP2 / 登高车 / 低压电工 / 高压电工 / 工具库）。
- 矩阵前三列为员工姓名 / UID / 专业组，文字居中并固定在左侧；横向滚动时三列保持可见，专业组右侧带轻微投影。
- 顶部统计：满编 50、当前在册 40、计划持证 40、实际持证、可拿未拿、60 天内到期。
- 培训、体检通过但尚未取得实际授权的显示「可拿」，不展示待培训 / 待体检；不提供系统内发放、续期、撤销、恢复动作。
- 实际授权自动关联同名人员属性勋章，取得即默认 3 星，不展示取得次数；授权过期或撤销后从人员勋章中剔除，重新取得后自动恢复。
- 点击人员行打开居中详情，展示 12 类授权、基础资格、属性勋章与授权记录；员工页面顶部只显示本人持证、可拿未拿、60 天内到期。
- 授权状态统一由 `ITO.authStatus(validTo)` 按演示日期实时计算（>60 天有效、≤60 天临期、过期），授权矩阵、成员详情、我的任务卡、值班页与大屏 08 面板共用同一口径；临期统计与提醒为 60 天窗口。员工顶部统计按授权项数计。
- `?demo=YYYY-MM-DD` 固定演示日时，任务等数据整体平移到演示日，而授权有效期锚定真实日历不平移——便于把演示日拨到未来测试授权到期与勋章剔除，属有意设计。
- 审计留痕覆盖：任务、巡检计划、维保计划、组织成员、作业授权、属性勋章、预警规则；详情中显示创建、最近更新、状态变更和操作记录。

### 4.12 任务、常规任务与工时

- 我的任务：员工只显示被分配的子任务与常规任务；主管 / 领导显示大修专项任务、我发起的任务、我负责的任务（含改派）。
- 巡检 / 维保计划新增执行人与标准工时；每个启用计划生成一条专项任务，提交记录后推进下一周期并生成下一期；异常巡检仍单独生成整改主任务。
- 工时负载：周容量 40h、月容量 160h，按截止日期归周 / 月；未完成用标准 / 计划工时，已完成用实际工时；值班按 8h/天计入常规负载，不生成任务。
- 大修管理一级菜单已呈现，当前为空状态；行动 / 物资 / 人员台账待字段确认后接入。

- 值班详情编辑保存后，详情头部状态立即同步。

## 5. 关键交互

| 动作 | 结果 |
| --- | --- |
| 新建任务 | 领导层、主管层可新建；新建字段默认留空，必填项字段下方提示；发起人选择领导时来源自动为「领导下发」，为空或本人时自动为自建；负责人只选主管 / 组长；可选择“保存草稿”或“创建并派发” |
| 保存草稿 | 生成 `T100xx` 但状态为草稿，不改变在办 / 超期 / 趋势；任务中心草稿筛选可编辑、删除、再次派发 |
| 创建并派发 | 生成主任务与 `T100xx-01…` 子任务，进入待分发，在办 +1、专业组 +1、新增 +1、趋势末项 +1 |
| 派发 | 选择组内执行人、截止时间、授权；成功后直接进入执行中 |
| 提交成果物 | 至少上传 1 个文件并填写成果说明；提交后进入审批中，负责人有 72 小时审批窗口 |
| 审批成果物 | 审批人可在线预览 / 下载成果物，通过或驳回；提交说明与审批意见分开保存 |
| 负责人审批通过 | 子任务闭环；全部子任务完成后主任务闭环 |
| 负责人审批驳回 | 子任务退回执行中，执行人重新完成并再次提交 |
| 审批超时 | 超过 72 小时自动变为已挂起，可继续审批或由执行人重新提交 |
| 重新提交 | 至少保留或上传 1 个新文件；生成新版本，历史版本保留，审批计时重置 |
| 编辑成果物 | 员工对本人已提交成果物追加、移除文件或修改说明；审批中/已挂起/执行中保存后重置审批计时并清空原审批意见；已完成保存为补充版本，不重新审批 |
| 编辑任务 | 草稿、待分发、执行中可修改名称、描述、等级、截止、标签与子任务执行信息 |
| 改派执行人 | 草稿、待分发、执行中可改派，保留当前任务状态并记录日志 |
| 取消任务 | 发起人 / 负责人在未完成阶段可取消，取消不计闭环、不计在办 |
| 超期筛选 | 状态下拉分「流程状态」「超期」；「超期」同时筛出未完成且过截止、以及已完成但完成时间晚于截止的子任务 |
| 汇总报审 | 领导下发任务闭环后，负责人至少上传 1 个汇总附件并提交领导审批；领导可在线预览 |

| 值班表 | 周值班表 + Excel 式六行值班表；主管 / 领导 / 管理员可编辑、导入、保存；模板与导出为带大标题的 XLSX |
| 维保登记 | 新增记录并顺延下次执行时间 |
| 授权续期 | 主管 / 领导可续期 / 撤销；仅主管可新增；员工只看本人授权，不显示操作 |
| 消息 | 点击打开详情；通知点击直达对应消息；可标为未读、全部已读；支持发送消息（标题 / 分组或选人 / 正文） |
| 规则 | 启停、新增、编辑、删除；状态即运行情况，不显示通知渠道；删除需二次确认 |
| 导出 | 任务、巡检、维保、授权、日志、月报均真实下载本地文件；任务导出包含成果物数量、文件名、提交说明、版本与汇总附件；员工层不导出授权 |
| 顶栏 | 不显示面包屑与全局搜索；保留日期、通知、驾驶舱入口、切换身份与用户 |

所有弹窗支持 `Esc` 关闭、点击遮罩关闭；提交前做必填校验；不允许假按钮。

## 7. 状态与刷新

当前为纯前端演示：

- 所有数据从 `ito-data.js` 深拷贝到 `ITO.state`，修改只存在内存；
- 刷新页面时任务与业务数据回到初始快照，成果物、成果说明、审批工作流通过 IndexedDB 回放；`sessionStorage` 只记住身份；
- 没有网络请求、没有真实鉴权；
- 接真实接口时，把页面提交回调中的“修改 state”替换为 API 调用，成功后再刷新 state。

## 9. 已知边界

- 演示数据为模拟数据，不代表真实生产指标。
- 员工身份固定为李工；其他员工的任务无法在四人演示身份中直接操作，主管可代为派发与审批，但提交成果只对执行人开放。
- 月报为前端生成的 HTML 文件，不是服务端报表。
- 成果物存 IndexedDB，清浏览器站点数据会丢失；不设应用层大小上限，但浏览器磁盘配额仍可能写入失败。
- Office 预览由本地库渲染，复杂版式可能与原文件存在差异；渲染失败会降级为下载。
- 预置样例只在首次加载或数据库重置后写入，不会覆盖用户新上传的文件。
- 权限矩阵与成果物可见性只控制前端，不构成真实安全边界；接后端后必须用服务端鉴权、对象存储签名 URL 与审计。
