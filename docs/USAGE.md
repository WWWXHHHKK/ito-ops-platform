# 使用指南

这份指南解决三个问题：

1. 我自己怎么打开、演示、截图？
2. 怎么把项目交给其他 agent 继续做，而且不让它跑偏？
3. 怎么把示例数据换成我们自己的业务数据？

---

## 1. 你手上有什么

| 文件 | 用途 | 给谁看 |
| --- | --- | --- |
| `index.html` | 可运行的深色驾驶舱页面 | 浏览器 / 开发者 |
| `admin.html` | 可运行的浅色管理后台 | 浏览器 / 开发者 |
| `assets/` | 两端的样式与交互逻辑 | 开发者 / agent |
| `vendor/echarts.min.js` | 本地图表库，离线可用 | 开发者 |
| `preview.png` | 1920×1080 大屏视觉基准 | 所有人，尤其是设计/agent |
| `admin-preview.png` | 管理后台视觉基准 | 所有人，尤其是设计/agent |
| `AGENTS.md` | 项目级规则，agent 进入项目先读 | 其他 agent |
| `docs/HANDOFF.md` | 大屏设计、模块、数据、验收规范 | 接手的开发者/agent |
| `docs/ADMIN.md` | 后台结构、角色、数据与交互 | 接手的开发者/agent |
| `docs/AGENT_PROMPT.md` | 可直接复制的交接提示词 | 你 / 其他 agent |
| `README.md` | 项目说明、运行方式、模块清单 | 所有人 |

**一句话理解**：`index.html` 是大屏成品，`admin.html` 是管理后台成品，两张 `*-preview.png` 是标准答案，`AGENTS.md + docs/HANDOFF.md + docs/ADMIN.md` 是防止别人把成品改成“另一个东西”的说明书。

### 1.1 两个入口怎么用

- 大屏看态势：打开 `index.html`，顶栏「管理后台」进入后台。
- 后台做管理：打开 `admin.html`，登录页选择身份，顶栏「驾驶舱大屏」返回。
- 后台演示可直接指定身份：`admin.html?role=leader`（领导层）、`manager`（主管层）、`employee`（员工层）、`admin`（系统管理员）。
- 想强制回到身份选择页，用 `admin.html?login=1`；登录后也可点左下角「切换身份」。
- 截图时加 `&still=1` 关闭入场与过渡动效。

## 2. 自己打开、演示、截图

### 2.1 直接打开

双击 `index.html`，用 Chrome / Edge 打开即可。项目没有 npm、没有构建步骤、没有外部 CDN，断网也能运行。

建议：

- 按 `F11` 进入全屏；
- 在 1920×1080 或更大的屏幕上展示效果最佳；
- 页面会自动等比缩放，小屏不会错位，但字会变小。

### 2.2 如果双击打不开

在项目目录启动一个本地静态服务：

```bash
python -m http.server 4173
```

浏览器访问：

```text
http://127.0.0.1:4173/
```

### 2.3 导出静态大屏截图

实时版有入场动画和滚动效果，直接截图可能截到动画中间。用静态模式：

```text
http://127.0.0.1:4173/?still=1
```

这个模式会关闭入场动画、雷达扫描、滚动快讯和脉冲，数字直接显示最终值。浏览器窗口设为 1920×1080 后截图，就是 `preview.png` 的效果。

### 2.4 演示时怎么讲

可以按这条线讲，基本覆盖整套界面：

> 这是 ITO 运维指挥中心驾驶舱。左边看任务健康、任务流量和巡检执行，中间看今日态势、任务流量沙盘、任务类型、超期时长和值班授权，右边看 SLA、维保和待办消息，最下面是运维快讯。数据是实时模拟的，可以暂停；中间列会自动轮播并支持人工切换，主要指标可点击下钻到后台对应模块。

## 3. 交给其他 agent 继续做

### 3.1 最重要的原则

**不要只发一张截图说“照这个做”。**

其他 agent 没有你的上下文，只给截图，它会自由发挥，最后大概率变成蓝紫霓虹、圆角玻璃卡片、营销大屏。

正确做法是发送**整个项目文件夹**（或下面的 zip），并明确告诉它先读：

1. `AGENTS.md`
2. `docs/HANDOFF.md`
3. `preview.png`

### 3.2 推荐流程

1. **先备份**：复制一份项目文件夹，避免 agent 改坏原版。
2. **只给一个任务**：一次只做一件事，比如“新增一个自动化任务面板”，不要一次让它“重做整个系统”。
3. **让它先复述**：要求它用 5 行说明它理解的项目定位、视觉方向和不可改项；确认没跑偏再让它写代码。
4. **要求截图自检**：改完必须给 1920×1080 截图、说明改了哪些文件、控制台是否报错。
5. **对照基准图验收**：和 `preview.png` 比，是否还是同一套视觉语言、同一套信息密度。

### 3.3 直接复制这段给它

```text
先读 AGENTS.md、docs/HANDOFF.md，并看 preview.png。这是现有的 ITO 运维驾驶舱，请严格沿用现有视觉语言、1920×1080 栅格、面板结构、数据单位和状态色，不要重做设计。

动手前先用 5 行复述你理解的项目定位、目标用户、视觉方向、不可改项和本次任务。

改完在 1920×1080 下截图自检，确认控制台无报错，并说明改了哪些文件、怎么验证的。

本次任务：【填写】
```

更多版本（短版 / 只确认理解版 / 常见任务的写法）见 `docs/AGENT_PROMPT.md`。

### 3.4 任务怎么拆

推荐顺序：

| 阶段 | 任务 | 目的 |
| --- | --- | --- |
| 1 | 替换品牌名、服务名、团队名、人员名 | 先让它变成“你们的系统” |
| 2 | 替换指标数值、时间、变更、告警 | 再让数据可信 |
| 3 | 新增 1 个面板 | 验证它是否理解现有设计语言 |
| 4 | 接入 1 个真实接口 | 验证它是否只改数据层 |
| 5 | 做下钻页（工单中心 / 告警中心） | 扩展同系列页面 |

不要一上来就做 5 个页面或整体换肤。

### 3.5 验收时看什么

- 1920×1080 截图是否完整，有没有溢出、裁切、空白断层；
- 主色、字体、斜切面板、编号、渐变描边是否还在；
- 数字是否自洽（健康分项=总数、拓扑图例=节点数、变更条目=底栏数字）；
- 控制台是否无报错；
- 趋势切换、事件筛选、暂停/恢复、拓扑悬浮是否还能用；
- `?still=1` 是否还能作为完整静态大屏。

如果不对，不要让它“再改改看”，直接把 `preview.png` 和 `AGENTS.md` 里对应的“不可破坏的基准”指给它。

## 4. 换成自己的业务数据

### 4.1 改哪里

| 要改的内容 | 位置 |
| --- | --- |
| 品牌名、顶栏文案 | `index.html` 顶栏 `.tp-box`、`.topbar-meta` |
| 服务名、团队名、拓扑节点 | `index.html` 中 `.topo-nodes` 里的 `<g class="node">` |
| 工单趋势数据 | `assets/js/app.js` 的 `TREND` |
| 实时事件种子与事件池 | `assets/js/app.js` 的 `events`、`eventPool` |
| 资源负载基值 | `assets/js/app.js` 的 `RES_BASE` |
| 任务类型、超期时长、值班人员 | `index.html` 对应面板的静态结构 |
| 配色、字体、斜切角、间距 | `assets/css/style.css` 的 `:root` 和对应组件 |
| 模块数量、栅格布局 | `assets/css/style.css` 的 `.grid`、`.col-*` |

### 4.2 改数据时守住三条

1. **数字自洽**：改了健康分项，要同步改总数；改了拓扑节点状态，要同步改图例。
2. **单位不能丢**：`ms`、`m`、`s`、`req/s`、`vCPU`、`TB`、`Gbps`、`单`、`条`。
3. **状态色不能乱**：正常=青绿，告警=黄，故障=红，监控中=青，变更=紫。

### 4.3 接真实接口

不要自己乱接。把 `docs/HANDOFF.md` 的 **7.4 接入真实数据** 那一节直接发给 agent，并加一句：

```text
只替换数据层，不要改现有 DOM 结构、视觉令牌和交互方式。先给我数据流设计，再写代码。
```

当前实时效果是前端模拟：

- 事件流每 9 秒新增；
- 资源负载每 6 秒抖动；
- 时间戳每 5 秒刷新。

接后端时，把这些模拟逻辑替换成 WebSocket / SSE / 轮询即可。

## 5. 其他使用方式

### 5.1 集成到现有系统

- **独立大屏**：直接部署 `index.html + assets + vendor` 到 Nginx 等静态服务器；
- **嵌入现有后台**：用 iframe 嵌入，或把页面作为独立路由；
- **Vue / React 项目**：把面板拆成组件，保留 CSS 令牌和 SVG 拓扑结构，ECharts 继续用本地包；
- **注意**：它按 1920×1080 设计，嵌入小窗口时会等比缩小，适合大屏/全屏路由，不适合塞进 400px 宽的卡片。

### 5.2 用来写需求 / 答辩 / 汇报

- 把 `docs/HANDOFF.md` 当作需求说明或设计规范；
- 把 `preview.png` 当作效果图；
- 把 `README.md` 的模块表当作功能清单；
- 把“数字自洽”与“验收清单”当作测试用例。

### 5.3 团队协作

- 设计师：看 `preview.png` 和 `docs/HANDOFF.md` 第 2 节；
- 前端：看 `index.html`、`style.css`、`app.js`；
- 后端：看 `docs/HANDOFF.md` 第 5、7.4 节的数据契约；
- 其他 agent：先读 `AGENTS.md`，再读 `HANDOFF.md`，最后看实现。

## 6. 常见问题

**Q：其他 agent 不看文档，直接开始写代码怎么办？**
A：在提示词里明确写“先复述，再动手”，并要求它把复述发给你确认。它如果直接改，就中断，把 `AGENTS.md` 的“不可破坏的基准”贴给它。

**Q：它改出来的风格不对，但功能是对的，怎么办？**
A：不要继续口头描述“再高级一点”。直接给它 `preview.png`，指出偏离了哪几条“六个必须保留的识别点”，让它只修视觉，不动功能。

**Q：我想换成蓝色主题可以吗？**
A：当前版本已经是深海蓝 + 青蓝 HUD。如果要换品牌色，先确认是“换强调色”还是“换整套视觉”。只改 `--cyan` 很可能会破坏主色层级，建议同时调整 `--blue`、发光强度和状态映射，并重新截图核对。

**Q：为什么数字在动？可以关掉吗？**
A：这是模拟实时感。点顶栏暂停按钮即可冻结数据与装饰动效；截图用 `?still=1`。

**Q：字体为什么和我电脑上不一样？**
A：数字优先用 Bahnschrift，Mac 上会回退到 DIN / Segoe UI；中文回退到苹方/思源黑体。若要完全一致，需要把字体文件放进项目并加 `@font-face`。

**Q：能直接上线吗？**
A：可以，但先把模拟数据替换成真实接口，并确认浏览器兼容、静态资源路径、内网访问权限。当前版本没有登录、权限和后端。

---

## 7. 最后一条建议

把 `preview.png` 当作“验收合同”。

每次 agent 改完，不要只看它说“完成了”，而是看三样东西：

1. 1920×1080 截图；
2. 控制台是否报错；
3. 和 `preview.png` 是不是同一套东西。

只要这三样守住，其他 agent 就不容易把它改成另一个项目。
