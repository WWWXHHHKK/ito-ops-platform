## 1. 口径说明

### 1.1 目的与边界

这份字典回答三个问题：

1. 页面上每个数字叫什么、怎么算、从哪里来。
2. 哪些数字是演示固定值，哪些是当前前端真实计算值。
3. 哪些数字已经下线、哪些只是建议新增，不能拿来做验收。

它不替代接口文档。接入真实系统时，只替换数据层，不改变页面的 DOM 结构、视觉令牌和交互方式；指标 ID、公式和展示位置保持不变。

### 1.2 取数优先级

出现口径冲突时，按以下顺序取数：

1. **当前页面实际显示值**：以 1920×1080 下的页面为准。
2. **当前前端代码计算值**：`assets/js/ito-data.js` 与各页面模块的运行时结果。
3. **当前文档**：`docs/ADMIN.md`、`docs/HANDOFF.md` 中仍与页面一致的部分。
4. **建议口径**：尚未接入页面、只在本字典中定义的指标。

`docs/HANDOFF.md` 仍保留旧版“服务健康 96.8%、工单 286/271、服务 SLA 99.972%”等口径，这些数字已不在当前大屏展示。本字典将它们标记为 `D` 历史指标，只用于对照，不参与当前验收。

数据日期与演示时间自动跟随系统；使用 `?demo=` 回归时快照时间固定为 20:56（内部口径，界面不展示）。本文所有“当前值”均按 **2026-11-03 20:56** 的基准快照维护；数据层基准日为 2026-11-02，运行时整体平移。跨午夜后页面会刷新，指标值随快照平移，公式不变。

| 层级 | 名称 | 回答的问题 | 典型指标 |

### 1.5 状态码与值模式

| 状态 | 含义 | 验收处理 |
| --- | --- | --- |
| `P` | 页面或数据字典已展示，值来自固定快照、文档或页面固定文案 | 可以验收展示，但不能当作实时计算 |
| `C` | 由当前前端数据计算，可复算 | 可以验收计算逻辑 |
| `G` | 建议新增，当前无完整取数链路 | 只验收口径，不验收数字 |
| `D` | 历史口径，已从当前页面下线 | 只做对照，不参与当前验收 |

| 值模式 | 含义 |
| --- | --- |
| 固定 | 数据快照或页面写死的文案，刷新后不变 |
| 计算 | 由任务、人员、授权、巡检等数据实时计算 |
| 建议 | 公式已定义，但缺少字段或台账，当前不给值 |
| 历史 | 旧版大屏或旧文档的值，保留用于差异核对 |

### 1.6 公式约定

- **比率**：`分子 ÷ 分母 × 100%`，默认保留 1 位小数；整数百分比只在页面明确写整数时使用。
- **计数**：默认是“当前时点”的快照；写明“近 30 天”的，按滚动 30 天统计。
- **分布**：各分组之和必须等于总数；不等时先查状态推导，不要改分母。
- **时效**：优先用 `completedAt`、`submittedAt`、`dueAt` 等真实字段；字段缺失时写“—”，不要用 0 代替。
- **多值指标**：当前值写成“应用 42 / 通信 33 / 在线 29 / 基础设施 24”这种形式，CSV 中保持同一字符串。
- **目标与预警**：只使用页面、文档或业务规则中已有的阈值；没有依据的不新造阈值。
- **实体边界**：主任务、子任务、服务、人员是不同实体。相同数字（例如 128）不代表同一件事。

### 1.7 与标签字典的关系

标签回答“这件事是什么、涉及谁、有什么风险”，指标回答“有多少、占比多少、是否达标”。两者不互相替代：

- 200 个标签的定义、映射和治理见 `docs/TAGS.md`。
- 标签覆盖率、标签引用数、平均标签数等指标归入 `DAT` 域。
- 标签本身不是指标；不要为了做指标把“紧急”“审批中”“应用组”等结构化字段重复建成标签。

## 4. 二十个核心指标卡

> 选卡标准：管理者在 30 秒内最可能追问的 20 个问题。每张卡都能在大屏或后台找到对应位置；数值与 2026-11-03 20:56 快照一致。

### 4.1 在办任务 `TSK-ACTIVE`

- **公式**：当前时点未闭环主任务计数。
- **当前值**：128 件。
- **目标 / 预警**：≤130 / >140。
- **读法**：这是任务压力盘的总量，不是“纳管服务数”。四组在办 42 + 33 + 29 + 24 = 128，必须与 `GRP-ACTIVE` 相等。
- **注意**：旧版服务健康也有 128，但实体是“服务”，不是“任务”，不能互相引用。

### 4.2 积压平衡 `TSK-BACKLOG-BALANCE`

- **公式**：`(期初积压 + 近 30 天新增 − 近 30 天闭环) ÷ 当前在办`。
- **当前值**：`(86 + 384 − 342) ÷ 128 = 100.0%`。
- **目标 / 预警**：100% / 不等于 100% 即口径异常。
- **读法**：这是全平台最重要的一条恒等式。它同时约束 `TSK-ACTIVE`、`TSK-NEW-30D`、`TSK-CLOSED-30D`、`TSK-OPENING-BACKLOG` 四个数。
- **注意**：只改其中一个数，页面就会出现“看起来都对、加起来不对”的问题。

### 4.3 超期任务 `TSK-OVERDUE`

- **公式**：主任务含任一未完成且已过截止时间的子任务，即计为超期。
- **当前值**：7 件；分组为应用 1 / 通信 2 / 在线 2 / 基础设施 2。
- **目标 / 预警**：0 / >5。
- **读法**：先看总量，再看分组。基础设施组超期率最高（8.3%），通信组和在线组各 2 件。
- **注意**：高风险 3 = 超期 ∩ 紧急；紧急在办是 4，其中 1 件今晚 23:00 才到期，尚未超期。

### 4.4 待处理事项 `TSK-PENDING`

- **公式**：待分发 + 审批中 + 已挂起子任务 + 审批中/已挂起的领导审批。
- **当前值**：9 项 = 7 个子任务（3 待分发 + 4 审批中）+ 2 个领导审批。
- **目标 / 预警**：≤5 / >10。
- **读法**：这是“需要人动手”的口径，不等于“审批待办”。仅审批口径是 6 项。
- **注意**：大屏 11 和后台派发与审批的角标应使用 9；如果只显示 6，说明漏掉了待分发。

### 4.5 任务 SLA `SLA-TASK`

- **公式**：按期闭环率 × 60% + 超期控制率 × 25% + 时效达成率 × 15%，滚动 30 天。
- **当前值**：92.0 分 / A 级，目标 ≥90 分。
- **目标 / 预警**：≥90 / <80。
- **读法**：这是平台级北极星指标，回答“承诺有没有守住”。
- **注意**：92.0 分为方案 A 加权综合分；按期率 89.0% 与前 8 条样本复算 75.0% 的差异保留为诊断值，不替换页面。

### 4.6 按期闭环率 `SLA-ONTIME`

- **公式**：截止时间前完成的子任务 ÷ 已闭环子任务。
- **当前值**：89.0%（页面固定值）；样本复算 6/8 = 75.0%。
- **目标 / 预警**：≥95% / <90%。
- **读法**：大屏 01 的环形图和 09 的明细都应显示 89.0%。
- **注意**：89.0% 与 75.0% 的差额来自固定值与样本口径，不要用其中一个去改另一个。

### 4.7 超期率 `SLA-OVERDUE-RATE`

- **公式**：未完成且已过截止的子任务 ÷ 在办任务。
- **当前值**：`7 ÷ 128 = 5.47%`，展示 5.5%。
- **目标 / 预警**：≤3% / >5%。
- **读法**：当前已越过 5% 预警线，但未到严重区。
- **注意**：分母是 128 在办任务，不是 23 子任务；子任务口径是 30.4%，见 `SLA-SUB-OVERDUE`。

### 4.8 平均闭环时长 `SLA-AVG-CLOSE`

- **公式**：Σ闭环耗时 ÷ 已闭环数，滚动 30 天。

- **注意**：当前数据没有创建时间，6h12m 是页面固定文案，不能复算。

### 4.9 专业组负荷指数 `GRP-LOAD-INDEX`

- **当前值**：121 / 128 = 96.8%（历史）。
- **目标 / 预警**：≥99% / <95%。
- **读法**：旧版大屏 01 的“全域健康”。121 健康 + 5 告警 + 2 故障 = 128 纳管服务。
- **注意**：当前大屏 01 已改为“任务健康”，不再展示这个指标；只用于和旧版文档对照。

### 4.19 服务 SLA `HLT-SLA`

- **公式**：达标服务 ÷ 纳管服务。
- **当前值**：99.972%（历史）。
- **目标 / 预警**：≥99.95% / <99.9%。
- **读法**：旧版大屏 09 的服务可用性口径，配 MTTR 18m24s、MTTA 2m48s、一次解决率 92.4%。
- **注意**：99.972% 与当前“任务 SLA 92.0 分”不是同一指标；前者是服务可用性，后者是任务时效综合分。

### 4.20 审批 72h 及时率 `SLA-APPROVAL-72H`

- **公式**：审批时长 ≤72h 的待审批事项 ÷ 待审批事项。
- **当前值**：3 / 6 = 50.0%。
- **目标 / 预警**：≥95% / <80%。
- **读法**：6 项待审批中 3 项已超 72h；平均年龄 75.4h，最长 131.9h（T10027-03）。
- **注意**：审批超时同时受 `submittedAt + 72h` 和 `dueAt` 两条规则约束；当前 3 项在两个口径下都超时。

### 5.1 五条必须始终成立的等式

1. `42 + 33 + 29 + 24 = 128`：四组在办 = 在办任务。
2. `86 + 384 − 342 = 128`：期初积压 + 新增 − 闭环 = 当前在办。

4. `3 待分发 + 4 审批中 + 2 领导审批 = 9`：待处理事项。
5. `121 + 5 + 2 = 128`：旧版健康 + 告警 + 故障 = 纳管服务（历史口径）。

任何一条不成立，先查状态推导和数据平移，不要直接改页面数字。

## 7. 治理规则

### 7.1 单一数据源

- 后台任务、人员、专业组、值班、授权、消息、规则、日志、标签成就、权限，统一来自 `assets/js/ito-data.js`。
- 页面模块不得各自复制一份任务或人员数据；新增页面只能读同一份数据。
- 大屏的固定值与后台的计算值必须在指标 ID 层对齐，不能各自命名。

### 7.2 命名与新增

- 指标 ID：`域-名称`，全大写，单词间用连字符，例如 `SLA-APPROVAL-72H`。
- 指标名称：中文，2–12 字，避免“总数”“情况”这类无法区分的词。
- 新增指标必须同时提供：业务定义、公式、分子、分母、时间窗、单位、精度、方向、目标、预警、当前值、值模式、状态、展示位置、数据源、关联标签、口径备注。
- 没有公式的指标不允许进入 `P` / `C`；只能标 `G` 或 `D`。

### 7.3 精度与舍入

- 比率默认 1 位小数，采用四舍五入。
- 不允许“先截断再四舍五入”造成二次误差。
- 多值分布保留原始整数，不强行凑成 100%。
- 百分比合计与 100% 的差异在底栏或注释中说明。

### 7.4 目标与预警

- 目标值只来自页面文案、`docs/ADMIN.md`、`docs/HANDOFF.md` 或明确业务规则。
- 没有依据时不新造阈值；可以在指标卡中写“无固定目标”。
- 预警值必须能从事后数据复算，不能只写“关注”。

### 7.5 下线与保留

- 指标下线不删除记录，状态改为 `D`，保留至少 180 天。
- 旧指标被新指标替代时，在冲突矩阵中写明替代关系。
- 历史指标不参与当前页面验收，但可用于月度对比和事故复盘。

### 7.6 演示值与真实值

- 演示值必须标 `P`，并在“口径备注”中写明“固定”或“页面文案”。
- 计算值标 `C`，公式必须能在当前数据上复算。
- 接真实接口时，先替换 `P`，再核对 `C`；不要为了让数字好看改分母。
- 每次改数据层，必须重跑本文第 8 节的验收清单。

### 7.7 评审节奏

- 每季度评审一次：清理 90 天未使用的指标，合并同义指标，补充新页面指标。
- 每次评审更新 `docs/METRICS.md`、`docs/metrics.csv` 和对应页面注释。
- 变更记录写入操作日志，至少保留 180 天。
